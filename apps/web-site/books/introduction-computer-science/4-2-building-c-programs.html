Introduction to C

Giới thiệu về C

The C programming language was invented in 1972 by Dennis Ritchie of Bell Labs (Figure 4.15) and popularized by the book The C Programming Language by Brian Kernighan and Dennis Ritchie. C’s peculiar name—a single letter—was a pragmatic choice, since C replaced an earlier language named B. C is a procedural, middle-level language that gives programs low-level access to memory. It is a relatively simple language, which makes learning C, and creating a C compiler, easier than for more complex languages. This combination of features made C an instant hit, and it has maintained great popularity and import to this day. C has influenced other programming languages, too. C++ is a newer language that adds the object-oriented paradigm to C.

Ngôn ngữ lập trình C được phát minh vào năm 1972 bởi Dennis Ritchie của Bell Labs (Hình 4.15) và được phổ biến qua cuốn sách Ngôn Ngữ Lập Trình C của Brian Kernighan và Dennis Ritchie. Tên gọi đặc biệt của C—một chữ cái duy nhất—là một lựa chọn thực dụng, vì C thay thế một ngôn ngữ trước đó có tên là B. C là một ngôn ngữ quy trình, cấp giữa, cho phép các chương trình truy cập bộ nhớ ở mức thấp. Đây là một ngôn ngữ tương đối đơn giản, điều này làm cho việc học C và tạo ra một compiler trở nên dễ dàng hơn so với các ngôn ngữ phức tạp hơn. Sự kết hợp các tính năng này đã khiến C trở thành một cú hit ngay lập tức, và nó vẫn duy trì được sự phổ biến và tầm quan trọng cho đến ngày nay. C cũng đã ảnh hưởng đến các ngôn ngữ lập trình khác. C++ là một ngôn ngữ mới hơn, bổ sung thêm mô hình lập trình hướng đối tượng vào C.

Why is C so popular? Mainly because its designers managed to strike a balance between low-level and middle-level features that allows C code to execute at practically the same speed as assembly language, while allowing programmers to be productive enough to create large, dependable, programs. C is the programming language behind much of the lower-level software that we depend on, including operating systems, language compilers, assemblers, text editors, print servers, network drivers, language interpreters, and command-line utilities. Applications of C

Các ứng dụng của C

C is used in a variety of industries. One example is astrophysics, where scientists write programs that simulate the motion of stellar bodies, and control instruments such as telescopes. Owing to the large size of the universe, these simulations involve performing calculations on very large arrays of numbers. C’s ability to execute fast, and control the layout of large arrays in memory, is advantageous for this application. As a relatively simple language, C is approachable to physicists who are not necessarily expert in computer science. Scientific experiments need to be reproducible, which means that code involved in science needs to work even decades in the future. The fact that C has been a stable, popular language for so long means that it is very likely to endure, which cannot be said of newer niche languages.

C được sử dụng trong nhiều ngành công nghiệp khác nhau. Một ví dụ là thiên văn học, nơi các nhà khoa học viết các chương trình mô phỏng chuyển động của các thiên thể và điều khiển các thiết bị như kính viễn vọng. Do kích thước lớn của vũ trụ, các mô phỏng này liên quan đến việc thực hiện các phép tính trên các mảng số rất lớn. Khả năng thực thi nhanh chóng của C và kiểm soát cách bố trí của các mảng lớn trong bộ nhớ là lợi thế cho ứng dụng này. Là một ngôn ngữ tương đối đơn giản, C dễ tiếp cận với các nhà vật lý không nhất thiết phải là chuyên gia trong lĩnh vực khoa học máy tính. Các thí nghiệm khoa học cần phải có thể tái tạo, điều này có nghĩa là mã liên quan đến khoa học cần phải hoạt động ngay cả hàng thập kỷ trong tương lai. Thực tế là C đã là một ngôn ngữ ổn định và phổ biến trong một thời gian dài có nghĩa là nó rất có khả năng tồn tại, điều này không thể nói về các ngôn ngữ mới hơn trong các lĩnh vực hẹp.

One notable feature of C is the way it handle memory. In a program, we have variables and values. For example, in x = 10, x is a variable and 10 is the value. Every value in a program is stored in memory. Memory regions are divided into four blocks: stack, heap, static, and code blocks. These regions store various parts of a running program. Running programs create and destroy values extremely rapidly (perhaps millions or billions per second), and memory is finite, so memory locations must be reused, or else would run out quickly. When a value is created, memory is set aside as allocated memory to hold that value. Eventually, when the value is no longer needed, that memory becomes freed memory, meaning it is given back so that it can be reused. The process of allocating and freeing memory is called memory management. A memory leak happens when some memory is allocated but never freed. A memory leak is a bug that causes a program to waste resources; severe leaks can waste all the memory on the computer, causing it to become unresponsive or crash. As a middle-level programming language, C requires programmers to handle memory management manually. This type of flexibility must be used with caution as it may result in creating programs that are not reliable and secure. In high-level languages, memory management is automated.

Một đặc điểm nổi bật của C là cách nó xử lý bộ nhớ. Trong một chương trình, chúng ta có các biến và giá trị. Ví dụ, trong x = 10, x là một biến và 10 là giá trị. Mỗi giá trị trong một chương trình được lưu trữ trong bộ nhớ. Các vùng bộ nhớ được chia thành bốn khối: ngăn xếp, heap, tĩnh và khối mã. Những vùng này lưu trữ các phần khác nhau của một chương trình đang chạy. Các chương trình đang chạy tạo ra và phá hủy các giá trị cực kỳ nhanh chóng (có thể hàng triệu hoặc hàng tỷ mỗi giây), và bộ nhớ là có hạn, vì vậy các vị trí bộ nhớ phải được tái sử dụng, nếu không sẽ nhanh chóng hết. Khi một giá trị được tạo ra, bộ nhớ được dành riêng như bộ nhớ đã cấp phát để chứa giá trị đó. Cuối cùng, khi giá trị không còn cần thiết, bộ nhớ đó trở thành bộ nhớ đã giải phóng, có nghĩa là nó được trả lại để có thể được tái sử dụng. Quá trình cấp phát và giải phóng bộ nhớ được gọi là memory management. Một memory leak xảy ra khi một số bộ nhớ được cấp phát nhưng không bao giờ được giải phóng. Một memory leak là một lỗi khiến chương trình lãng phí tài nguyên; những rò rỉ nghiêm trọng có thể lãng phí toàn bộ bộ nhớ trên máy tính, khiến nó trở nên không phản hồi hoặc bị treo. Là một middle-level programming language, C yêu cầu lập trình viên phải xử lý memory management một cách thủ công. Loại linh hoạt này phải được sử dụng cẩn thận vì nó có thể dẫn đến việc tạo ra các chương trình không đáng tin cậy và an toàn. Trong các ngôn ngữ cấp cao, memory management được tự động hóa.

Efficient execution: C is lower in expressive power than some other middle-level languages like C++ and yet simple enough that compilers can generate machine code that is comparable in speed to hand-written assembly code. A lot of research and development have focused on creating performance-oriented C compilers.

Thực thi hiệu quả: C có sức biểu đạt thấp hơn một số ngôn ngữ trung cấp khác như C++ và vẫn đủ đơn giản để các trình biên dịch có thể tạo ra machine code có tốc độ so sánh được với mã lắp ráp viết tay. Rất nhiều nghiên cứu và phát triển đã tập trung vào việc tạo ra các trình biên dịch C hướng tới hiệu suất.
  3. Portability: C can run in multiple computing environments, also known as having the property of portability. Unix was designed to work on various hardware architectures, so the C language is not hardware-dependent. Unix được thiết kế để hoạt động trên nhiều kiến trúc phần cứng khác nhau, vì vậy ngôn ngữ C không phụ thuộc vào phần cứng. Mã C giống nhau có thể được biên dịch và thực thi trên các kiến trúc phần cứng và hệ điều hành khác nhau.
  5. Modularity: Modular programming refers to the process of dividing computer programs into separate sub-programs. A module is a separate software component, such as an error handler, that may be used by a variety of applications and functions within a system. C has language support for modularity.
  6. Modularity: Lập trình mô-đun đề cập đến quá trình chia nhỏ các chương trình máy tính thành các chương trình con riêng biệt. Một mô-đun là một thành phần phần mềm riêng biệt, chẳng hạn như một trình xử lý lỗi, có thể được sử dụng bởi nhiều ứng dụng và chức năng khác nhau trong một hệ thống. C có hỗ trợ ngôn ngữ cho modularity.
  7. Procedural and structured programming support: C adheres to the procedural and structured paradigms.
  8. Lập trình quy trình và structured programming hỗ trợ: C tuân thủ các mô hình quy trình và lập trình có cấu trúc.
  9. Data types and operators: Every variable in a C program has a data type. Data types dictate how much memory is used to store the variable, and which kinds of operators can be used with the variable.
  10. Các kiểu dữ liệu và operators: Mỗi biến trong một chương trình C đều có một kiểu dữ liệu. Các kiểu dữ liệu quy định lượng bộ nhớ được sử dụng để lưu trữ biến, và các loại toán tử nào có thể được sử dụng với biến đó.
  11. Recursion support: Recursion is the phenomenon of a system being defined in terms of itself. In code, this means a function may call itself again and again. C supports recursion. However, it does not provide a feature called “tail-calling” that makes recursion efficient, so recursion is not used in C as much as in languages that provide tail-calling. A tail call is a function call performed as the final action of a function. If the target function of a tail is the same function, the function is said to be tail recursive, which is a special case of recursion. Tail recursion (also called “tail-end recursion”) is useful and helps with code optimizations.
  12. Hỗ trợ đệ quy: Đệ quy là hiện tượng của một hệ thống được định nghĩa theo chính nó. Trong mã, điều này có nghĩa là một function có thể gọi chính nó nhiều lần. C hỗ trợ đệ quy. Tuy nhiên, nó không cung cấp một tính năng gọi là “gọi đuôi” giúp đệ quy trở nên hiệu quả, vì vậy đệ quy không được sử dụng trong C nhiều như trong các ngôn ngữ cung cấp gọi đuôi. Một cuộc gọi đuôi là một cuộc gọi function được thực hiện như hành động cuối cùng của một function. Nếu function mục tiêu của một cuộc gọi đuôi là cùng một function, function đó được gọi là đệ quy đuôi, đây là một trường hợp đặc biệt của đệ quy. Đệ quy đuôi (còn được gọi là “đệ quy cuối”) là hữu ích và giúp tối ưu hóa mã.
  13. Pointers: A pointer is a variable that holds the memory address of another variable and points to that variable (Figure 4.16). Pointers play a crucial role in the C language. They are used to store and manage addresses of dynamically allocated blocks in memory in the underlying computer system. Managing hardware devices involves manipulating certain memory locations, and C’s support for pointers is one of the reasons that it is used to implement kernels and device drivers.
  14. Pointers: Một pointer là một biến giữ địa chỉ bộ nhớ của một biến khác và trỏ đến biến đó (Hình 4.16). Pointers đóng vai trò quan trọng trong ngôn ngữ C. Chúng được sử dụng để lưu trữ và quản lý địa chỉ của các khối được cấp phát động trong bộ nhớ của hệ thống máy tính cơ sở. Quản lý các thiết bị phần cứng liên quan đến việc thao tác với một số vị trí bộ nhớ nhất định, và sự hỗ trợ của C cho pointers là một trong những lý do mà nó được sử dụng để triển khai kernel và device driver.

C’s Application in the Early Stages of YouTube

Ứng dụng của C trong giai đoạn đầu của YouTube

C has a variety of integer types, such as short, int, and long. A C programmer needs to decide on the most appropriate type for each piece of information in their program. Smaller types use less memory but can only store a narrower range of values. On a typical computer, the maximum short value is about 32 thousand and the maximum int value is about 2 billion. A good practice is to think critically about how large a particular value might become and pick the smallest data type that accommodates that range.

C có nhiều loại số nguyên, chẳng hạn như short, int, và long. Một C lập trình viên cần quyết định loại nào là phù hợp nhất cho từng thông tin trong chương trình của họ. Các loại nhỏ hơn sử dụng ít bộ nhớ hơn nhưng chỉ có thể lưu trữ một phạm vi giá trị hẹp hơn. Trên một máy tính điển hình, giá trị tối đa của short khoảng 32 nghìn và giá trị tối đa của int khoảng 2 tỷ. Một thực hành tốt là suy nghĩ một cách phản biện về kích thước của một giá trị cụ thể có thể trở thành và chọn loại dữ liệu nhỏ nhất có thể chứa phạm vi đó.

The YouTube programmers faced this issue when they implemented the view counter for YouTube videos. They had to think through: what is the maximum number of views that a video is likely to garner? Two billion seemed like a safe choice, so they chose int.

Các lập trình viên YouTube đã gặp phải vấn đề này khi họ triển khai bộ đếm lượt xem cho các video trên YouTube. Họ phải suy nghĩ: số lượt xem tối đa mà một video có khả năng thu hút là bao nhiêu? Hai tỷ có vẻ như là một lựa chọn an toàn, vì vậy họ đã chọn int.

This decision turned out to be misguided. In 2014, the viral hit music video “Gangnam Style” by the Korean artist Psy accumulated more than two billion views, and the view counter broke. The int variable storing the number of views of “Gangnam Style” overflowed and wrapped around to a negative number. This proved to be an embarrassment for YouTube, who had to quickly change their code to use long instead.

Quyết định này hóa ra là sai lầm. Vào năm 2014, video âm nhạc nổi tiếng “Gangnam Style” của nghệ sĩ Hàn Quốc Psy đã tích lũy được hơn hai tỷ lượt xem, và bộ đếm lượt xem đã bị hỏng. Biến int lưu trữ số lượt xem của “Gangnam Style” đã tràn và quay trở lại thành một số âm. Điều này đã chứng minh là một sự xấu hổ cho YouTube, họ đã phải nhanh chóng thay đổi mã của mình để sử dụng long thay thế.

High-level languages usually check array indices at runtime, which makes out-of-range bugs easy to identify and fix, but slows down array subscripts slightly. As a middle-level language, C does not check array indices. An array is a storage space where the elements are stored in contiguous memory cells. They are indexed from 0 (the first cell) to n−1 (last cell).

Ngôn ngữ cấp cao thường kiểm tra chỉ số mảng tại thời gian chạy, điều này làm cho các lỗi ngoài phạm vi dễ dàng được xác định và sửa chữa, nhưng làm chậm một chút các chỉ số mảng. Là một ngôn ngữ cấp trung, C không kiểm tra chỉ số mảng. Một mảng là một không gian lưu trữ nơi các phần tử được lưu trữ trong các ô nhớ liên tiếp. Chúng được đánh chỉ số từ 0 (ô đầu tiên) đến n−1 (ô cuối cùng).

In C, an invalid array subscript will access memory outside of the array variable. If the subscript is only out of range by a little bit, this will access nearby variables, which is a subtle bug that may go unnoticed. A segmentation fault (“segfault” for short) occurs if the subscript is very far out of range. When this occurs, it will access a memory address that is off-limits to the program, and your operating system will forcibly shut down the program in response. This kind of runtime error can be notoriously difficult to remedy. Out-of-bounds array subscripts are a common source of segmentation fault errors.

Trong C, một chỉ số mảng không hợp lệ sẽ truy cập vào bộ nhớ bên ngoài biến mảng. Nếu chỉ số chỉ vượt quá giới hạn một chút, điều này sẽ truy cập vào các biến gần đó, đây là một lỗi tinh vi có thể không được phát hiện. Một segmentation fault (“segfault” cho ngắn) xảy ra nếu chỉ số vượt quá giới hạn rất xa. Khi điều này xảy ra, nó sẽ truy cập vào một địa chỉ bộ nhớ mà chương trình không được phép, và hệ điều hành của bạn sẽ buộc phải tắt chương trình để phản ứng. Loại lỗi thời gian chạy này có thể rất khó khắc phục. Các chỉ số mảng vượt quá giới hạn là một nguồn phổ biến gây ra lỗi segmentation fault.

Every value in a program is stored at a specific memory address. A pointer is a value that contains a memory address. Technically, a pointer should contain the location of a valid data value. However, many memory locations do not contain valid data values, so it is possible to have an invalid pointer that does not hold a valid location. The pointee is the value that a pointer points at. A pointer is analogous to a street address such as “123 Main Street,” because it refers to a specific location. In that analogy, each building is a pointee. Usually, an address is valid and refers to a place you can visit. However, it is possible to have an invalid address that is not a place that can be visited; for example, if the building at that location was demolished.

Mỗi giá trị trong một chương trình được lưu trữ tại một địa chỉ bộ nhớ cụ thể. Một con trỏ là một giá trị chứa một địa chỉ bộ nhớ. Về mặt kỹ thuật, một con trỏ nên chứa vị trí của một giá trị dữ liệu hợp lệ. Tuy nhiên, nhiều vị trí bộ nhớ không chứa các giá trị dữ liệu hợp lệ, vì vậy có thể có một con trỏ không hợp lệ không giữ một vị trí hợp lệ. Giá trị mà con trỏ chỉ đến được gọi là pointee. Một con trỏ tương tự như một địa chỉ đường phố như “123 Main Street,” vì nó đề cập đến một vị trí cụ thể. Trong phép ẩn dụ đó, mỗi tòa nhà là một pointee. Thông thường, một địa chỉ là hợp lệ và đề cập đến một nơi mà bạn có thể đến thăm. Tuy nhiên, có thể có một địa chỉ không hợp lệ không phải là một nơi có thể đến thăm; ví dụ, nếu tòa nhà tại vị trí đó đã bị phá hủy.

One of the differences between middle-level and high-level languages is that high-level languages either prohibit invalid pointers entirely, or provide mechanisms to handle them safely. As a middle-level language, C gives programmers the freedom to create null/invalid pointers, which can be helpful when writing code that interfaces with hardware devices. Since all hardware devices do not support the same functionality, the support of individual features by a given device may be indicated as a null/uninitialized pointer, which is fine as long as the program checks for un-initialized pointers to determine if a given functionality is available. However, in general, the freedom of using null/invalid pointers comes with a responsibility to ensure that pointers are always used properly. This has proven to be difficult; invalid pointers are a common source of bugs in C programs.

Một trong những sự khác biệt giữa ngôn ngữ cấp trung và ngôn ngữ cấp cao là ngôn ngữ cấp cao hoàn toàn cấm các con trỏ không hợp lệ, hoặc cung cấp các cơ chế để xử lý chúng một cách an toàn. Là một ngôn ngữ cấp trung, C cho phép lập trình viên tự do tạo ra các con trỏ null/không hợp lệ, điều này có thể hữu ích khi viết mã tương tác với các thiết bị phần cứng. Vì không phải tất cả các thiết bị phần cứng đều hỗ trợ cùng một chức năng, việc hỗ trợ các tính năng riêng lẻ của một thiết bị nhất định có thể được chỉ định dưới dạng một con trỏ null/chưa khởi tạo, điều này là chấp nhận được miễn là chương trình kiểm tra các con trỏ chưa khởi tạo để xác định xem một chức năng nhất định có sẵn hay không. Tuy nhiên, nhìn chung, sự tự do sử dụng các con trỏ null/không hợp lệ đi kèm với trách nhiệm đảm bảo rằng các con trỏ luôn được sử dụng đúng cách. Điều này đã chứng minh là khó khăn; các con trỏ không hợp lệ là một nguồn gốc phổ biến của lỗi trong các chương trình C.

In C, the programmer is responsible for making sure that character arrays are actually big enough to fit strings, and that strings include the null terminator character. A character array is a string of characters sometimes terminated using a null. An example might be something like: char *arr= "string\0". Overlooking either of these results in bugs. This is a prime example of how middle-level languages such as C expect programmers to deal with more details than do high-level languages.

Trong C, lập trình viên có trách nhiệm đảm bảo rằng các mảng ký tự thực sự đủ lớn để chứa các chuỗi, và rằng các chuỗi bao gồm ký tự kết thúc null. Một mảng ký tự là một chuỗi các ký tự đôi khi được kết thúc bằng một null. Một ví dụ có thể là: char *arr= "string\0". Bỏ qua bất kỳ điều nào trong số này sẽ dẫn đến lỗi. Đây là một ví dụ điển hình về cách mà các ngôn ngữ cấp trung như C mong đợi lập trình viên xử lý nhiều chi tiết hơn so với các ngôn ngữ cấp cao.

Linking refers to the process of collecting and combining various pieces of object code into a single program file that can be loaded into memory and executed. A linker is a program that performs linking. Understanding linkers will help you build large programs, avoid dangerous programming errors, understand how language scoping rules are implemented, understand other important systems concepts (such as virtual memory and paging), and use shared libraries (a file that is to be shared by an executable file). Virtual memory is an operating system concept where the secondary memory acts as main memory to compensate for memory shortage. Paging is a technique where the secondary memory is used to store and retrieve the data into the main memory. The memory is divided into small regions called pages which enables for the quick access of the data. If a page is found, it is called a “Page hit;” otherwise, it is a “Page miss.”

Linkers are used to ensure:

Linker được sử dụng để đảm bảo:

  • Modularity: Program can be written as a collection of smaller source files, rather than one monolithic mass. Using a linker facilitates building libraries of common functions (e.g., Math library, standard C library). Also, libraries save memory space because common functions can be aggregated into a single file and yet executable files (the end product after compiling and linking) and running memory images (current memory) contain only code for the functions they actually use.
  • Hiệu quả: Nó tiết kiệm thời gian khi thực hiện các biên dịch riêng biệt và thay đổi một tệp nguồn, biên dịch, và sau đó liên kết lại vì không cần phải biên dịch lại các tệp nguồn khác. Executable and Linkable Module Format

There are three kinds of object files (modules) that relate to the linking process (Figure 4.22):

Có ba loại tệp đối tượng (module) liên quan đến quá trình liên kết (Hình 4.22):

  • Relocatable Object File (.o file): Contains code and data in a form that can be combined with other relocatable object files to form executable object file. Each .o file is produced from exactly one source (.c) file.
  • Tệp đối tượng có thể di chuyển (.o): Chứa mã và dữ liệu ở dạng có thể kết hợp với các tệp đối tượng có thể di chuyển khác để tạo thành tệp đối tượng thực thi. Mỗi tệp .o được tạo ra từ chính xác một tệp nguồn (.c).
  • Executable Object File (a.out file): Contains code and data in a form that can be copied directly into memory and then executed.
  • Tệp đối tượng thực thi (a.out): Chứa mã và dữ liệu ở dạng có thể được sao chép trực tiếp vào bộ nhớ và sau đó được thực thi.
  • Shared Object File (.so file): Special type of relocatable object file that can be loaded into memory and linked dynamically, at either load time or runtime. These object files are called Dynamic Link Libraries (DLLs) on Windows.
  • Tệp Đối Tượng Chia Sẻ (.so): Loại tệp đối tượng có thể di chuyển đặc biệt có thể được tải vào bộ nhớ và liên kết động, tại thời điểm tải hoặc thời gian chạy. Những tệp đối tượng này được gọi là Thư Viện Liên Kết Động (DLL) trên Windows.

All three object files follow the executable and linkable format (ELF) which is a standard binary format for object files originally proposed by AT&T System V Unix, and later adopted by BSD Unix variants and Linux. Unix is an operating system that has been used widely, primarily in servers and software development since the 1970s, and Linux is Unix-compatible.

Tất cả ba tệp đối tượng đều theo định dạng executable and linkable format (ELF) mà là một định dạng nhị phân tiêu chuẩn cho các tệp đối tượng được đề xuất ban đầu bởi AT&T System V Unix, và sau đó được các biến thể BSD Unix và Linux chấp nhận. Unix là một operating system đã được sử dụng rộng rãi, chủ yếu trong các máy chủ và phát triển phần mềm từ những năm 1970, và Linux tương thích với Unix.

Cũng lưu ý rằng các biến C không tĩnh cục bộ được lưu trữ trên ngăn xếp trong khi các biến C tĩnh cục bộ được lưu trữ trong .bss hoặc .data.

Program symbols are either strong (e.g., procedures and initialized globals) or weak (e.g., uninitialized globals). A strong symbol has a unique memory location. Let’s take the example of: int array[2] = {1 ,2};. This creates an ambiguity during the linking process when there is another file that tries to access the same symbol again due to strong definition. On the other hand, a weak symbol allows multiple definitions of the same symbol without creating an ambiguity. This helps during the linking process when another file creates a strong definition of the same name. In languages like C and C++, the weak symbol is defined using the _attribute_((weak)) keyword. Global variables should be avoided (i.e., use static whenever you can, initialize the global variable, or use extern if you reference an external global variable).

Các symbol trong chương trình có thể là mạnh (ví dụ: các thủ tục và biến toàn cục đã khởi tạo) hoặc yếu (ví dụ: các biến toàn cục chưa khởi tạo). Một symbol mạnh có một vị trí bộ nhớ duy nhất. Hãy lấy ví dụ: int array[2] = {1 ,2};. Điều này tạo ra sự mơ hồ trong quá trình liên kết khi có một tệp khác cố gắng truy cập cùng một symbol do định nghĩa mạnh. Mặt khác, một symbol yếu cho phép nhiều định nghĩa của cùng một symbol mà không tạo ra sự mơ hồ. Điều này giúp trong quá trình liên kết khi một tệp khác tạo ra một định nghĩa mạnh của cùng một tên. Trong các ngôn ngữ như C và C++, symbol yếu được định nghĩa bằng cách sử dụng từ khóa _attribute_((weak)). Các biến toàn cục nên được tránh (tức là, hãy sử dụng static bất cứ khi nào bạn có thể, khởi tạo biến toàn cục, hoặc sử dụng extern nếu bạn tham chiếu đến một biến toàn cục bên ngoài).

The linker applies the following rules:

Linker linker áp dụng các quy tắc sau:

  • Rule 1: Multiple strong symbols are not allowed. Each item can be defined only once, otherwise the linker issues an error.
  • Quy tắc 1: Nhiều ký hiệu mạnh không được phép. Mỗi mục chỉ có thể được định nghĩa một lần, nếu không, trình liên kết sẽ phát sinh lỗi.
  • Rule 2: Given a strong symbol and multiple weak symbols, choose the strong symbol (references to the weak symbol resolve to the strong symbol).
  • Quy tắc 2: Khi có một ký hiệu mạnh và nhiều ký hiệu yếu, hãy chọn ký hiệu mạnh (các tham chiếu đến ký hiệu yếu sẽ được giải quyết thành ký hiệu mạnh).
  • Rule 3: If there are multiple weak symbols, pick an arbitrary one (can override this with gcc –fno-common). “-fno-common” helps in catching accidental common name collisions.
  • Quy tắc 3: Nếu có nhiều ký hiệu yếu, hãy chọn một ký hiệu tùy ý (có thể ghi đè điều này bằng gcc –fno-common). “-fno-common” giúp phát hiện các va chạm tên chung không mong muốn.

Static Libraries

Thư viện tĩnh

Functions commonly used by programmers (e.g., math, I/O, memory management, string manipulation) can be packaged into a file called a library. A static library (or .a, an archive file) is a simple kind of library that that copies the contents of object files into a single file called an archive. The linker tries to resolve unresolved external references by looking for the symbols in one or more archives. An external reference is a symbol that is used in a module, but not defined in that module, so it is expected to be defined in some other module. If an archive member file resolves a reference, the linker links it into the executable. The archiver allows incremental updates; it also recompiles functions that changed and replaces the corresponding .o file in the archive (Figure 4.25).

Function thường được các lập trình viên sử dụng (ví dụ: toán học, I/O, memory management, thao tác chuỗi) có thể được đóng gói vào một tệp gọi là thư viện. Một static library (hoặc .a, một archive file) là một loại thư viện đơn giản mà sao chép nội dung của các tệp đối tượng vào một tệp duy nhất gọi là archive. Trình liên kết cố gắng giải quyết các external references chưa được giải quyết bằng cách tìm kiếm các ký hiệu trong một hoặc nhiều archive. Một tham chiếu bên ngoài là một ký hiệu được sử dụng trong một mô-đun, nhưng không được định nghĩa trong mô-đun đó, vì vậy nó được kỳ vọng sẽ được định nghĩa trong một mô-đun khác. Nếu một tệp thành viên của archive giải quyết một tham chiếu, trình liên kết sẽ liên kết nó vào tệp thực thi. Trình lưu trữ cho phép cập nhật gia tăng; nó cũng biên dịch lại các function đã thay đổi và thay thế tệp .o tương ứng trong archive (Figure 4.25).

Commonly used libraries include libc.a (the C standard library), which handles: I/O, memory allocation, signal handling, string handling, data and time, random numbers, and integer math. Another common library is libm.a (the C math library) that handles floating point math (e.g., sin, cos, tan, log, exp, sqrt).

Các thư viện thường được sử dụng bao gồm libc.a (thư viện chuẩn C), xử lý: I/O, cấp phát bộ nhớ, xử lý tín hiệu, xử lý chuỗi, dữ liệu và thời gian, số ngẫu nhiên, và toán học số nguyên. Một thư viện phổ biến khác là libm.a (thư viện toán học C) xử lý toán học số thực (ví dụ, sin, cos, tan, log, exp, sqrt).

Bộ liên kết sử dụng thuật toán sau để giải quyết các tham chiếu bên ngoài:

  1. Scan .o files and .a files in the command line order.
  2. Quét .o và .a theo thứ tự dòng lệnh.
  3. During the scan, keep a list of the current unresolved references.

  7. If any entries in the unresolved list at end of scan, then issue error.
  8. Nếu có bất kỳ mục nào trong danh sách chưa được giải quyết ở cuối quá trình quét, thì phát sinh lỗi.

Concepts In Practice

Các Khái Niệm Trong Thực Hành

APIs in C

APIs trong C

The C language makes it possible to create a modular API (Application Programming Interface) as a library with publicly visible function prototypes but secret function definitions. This is accomplished by distributing the .h files with function declarations freely, while keeping the .c files secret and instead distributing only .a or .so compiled object code. A .h file is used in C, C++, where the libraries can be used in the current program instead of writing the code completely.

Ngôn ngữ C cho phép tạo ra một API (Giao diện lập trình ứng dụng) mô-đun như một library với các nguyên mẫu hàm có thể nhìn thấy công khai nhưng định nghĩa hàm thì bí mật. Điều này được thực hiện bằng cách phân phối các tệp .h với các khai báo hàm một cách tự do, trong khi giữ bí mật các tệp .c và thay vào đó chỉ phân phối các mã .a hoặc .so đã biên dịch object code. Một tệp .h được sử dụng trong C, C++, nơi các thư viện có thể được sử dụng trong chương trình hiện tại thay vì viết toàn bộ mã.

An example is math.h. This strategy is used in many industries, such as video games. DirectX is an API created by Microsoft for the platforms that are used on Windows PCs and Xbox. Microsoft provides a C library with many function calls for game-related operations such as drawing graphics, playing sounds, and reading inputs from the keyboard, mouse, or joystick. A game programmer writes their game as a C program that calls those functions. This arrangement is a good compromise—the convenience of the DirectX API makes game programmers’ work easier, and entices them to create games for Windows and Xbox. But keeping the .c files proprietary means that Microsoft does not have to give away the hard work that went into creating DirectX, Windows, or Xbox.

Một ví dụ là math.h. Chiến lược này được sử dụng trong nhiều ngành công nghiệp, chẳng hạn như trò chơi điện tử. DirectX là một API được tạo ra bởi Microsoft cho các nền tảng được sử dụng trên máy tính Windows và Xbox. Microsoft cung cấp một thư viện C với nhiều lời gọi hàm cho các hoạt động liên quan đến trò chơi như vẽ đồ họa, phát âm thanh và đọc đầu vào từ bàn phím, chuột hoặc joystick. Một lập trình viên trò chơi viết trò chơi của họ dưới dạng một chương trình C gọi những hàm đó. Sự sắp xếp này là một thỏa hiệp tốt—sự tiện lợi của API DirectX giúp công việc của lập trình viên trò chơi trở nên dễ dàng hơn, và thu hút họ tạo ra trò chơi cho Windows và Xbox. Nhưng việc giữ các tệp .c là độc quyền có nghĩa là Microsoft không phải cho đi những nỗ lực khó khăn đã bỏ ra để tạo ra DirectX, Windows hoặc Xbox.

The same arrangement works on other platforms, too. OpenGL is a cross-platform API that works on almost every modern platform, and Sony PlayStation has a similar API. Both of these are distributed as C libraries with public .h files and proprietary implementations.

Sự sắp xếp tương tự cũng hoạt động trên các nền tảng khác. OpenGL là một API đa nền tảng hoạt động trên hầu hết mọi nền tảng hiện đại, và Sony PlayStation có một API tương tự. Cả hai đều được phân phối dưới dạng thư viện C với các tệp .h công khai và các triển khai độc quyền.

An object file is a file that is a combination of metadata from the source or object code along with a combination of bytecode

Một tệp đối tượng là một tệp kết hợp giữa siêu dữ liệu từ mã nguồn hoặc mã đối tượng cùng với một sự kết hợp của mã byte.

Dynamic Load-Time Linking
Liên kết Thời gian Tải Động

Static libraries have the following disadvantages: duplication in the stored executables (every function needs libc), duplication in the running executables, and minor bug fixes of system libraries require each application to explicitly relink. A modern solution to this problem is to use shared libraries (also called dynamic link libraries, DLLs, or .so files). A shared library is a library file that can be shared by multiple programs at the same time (Figure 4.28).

Thư viện tĩnh có những nhược điểm sau: sự trùng lặp trong các tệp thực thi đã lưu (mỗi hàm cần libc), sự trùng lặp trong các tệp thực thi đang chạy, và việc sửa lỗi nhỏ của các thư viện hệ thống yêu cầu mỗi ứng dụng phải liên kết lại một cách rõ ràng. Một giải pháp hiện đại cho vấn đề này là sử dụng thư viện chia sẻ (còn được gọi là thư viện liên kết động, DLL, hoặc .so tệp). Một thư viện chia sẻ là một tệp thư viện có thể được chia sẻ bởi nhiều chương trình cùng một lúc (Hình 4.28).

When using shared libraries, object files that contain code and data may be loaded and linked into an application dynamically at load time, as illustrated in Figure 4.29. This load time linking occurs when dynamic linking happens at the same time that a program executable is first run. This is a common case for Linux, which is handled automatically by the dynamic linker (ld-linux.so). The standard C library (libc.so) is usually dynamically linked. The ldd tool may be used to identify dependencies/libraries needed at load time. In static linking the routines code becomes a part of the executable. In dynamic linking, the routines can be updated during the code execution. To dynamically link a library at load time on Linux, place it in the /lib/x86_64-linux-gnu/ directory and compile the source files with the -l flag (e.g., gcc main.c -lcso).

Khi sử dụng thư viện chia sẻ, các tệp đối tượng chứa mã và dữ liệu có thể được tải và linking vào một ứng dụng một cách động tại thời gian tải, như được minh họa trong Hình 4.29. Việc linking tại thời gian tải xảy ra khi linking động diễn ra đồng thời với việc một chương trình thực thi lần đầu tiên được chạy. Đây là một trường hợp phổ biến cho Linux, được xử lý tự động bởi linker động (ld-linux.so). Thư viện C chuẩn (libc.so) thường được linking động. Công cụ ldd có thể được sử dụng để xác định các phụ thuộc/thư viện cần thiết tại thời gian tải. Trong linking tĩnh, mã của các thủ tục trở thành một phần của tệp thực thi. Trong linking động, các thủ tục có thể được cập nhật trong quá trình thực thi mã. Để linking động một thư viện tại thời gian tải trên Linux, hãy đặt nó vào thư mục /lib/x86_64-linux-gnu/ và biên dịch các tệp nguồn với cờ -l (ví dụ, gcc main.c -lcso).

Dynamic Runtime Linking
Liên kết thời gian chạy động

An alternative to load-time linking is runtime linking, which means that linking occurs after a program has already started running. As illustrated in the sample code, the program source code needs to explicitly call functions to link additional libraries. In Linux, this is done by calls to the dlopen() interface and compiling the source with the -l flag (e.g., gcc main.c -ldl). This is a better approach to help distribute software, support high-performance Web servers, or perform runtime library interpositioning.

Một phương pháp thay thế cho liên kết thời gian tải là liên kết thời gian chạy, có nghĩa là việc liên kết xảy ra sau khi một chương trình đã bắt đầu chạy. Như được minh họa trong đoạn mã mẫu, chương trình source code cần phải gọi rõ ràng các hàm để liên kết các thư viện bổ sung. Trong Linux, điều này được thực hiện bằng cách gọi đến giao diện dlopen() và biên dịch mã nguồn với cờ -l (ví dụ, gcc main.c -ldl). Đây là một cách tiếp cận tốt hơn để giúp phân phối phần mềm, hỗ trợ các máy chủ Web hiệu suất cao, hoặc thực hiện việc thay thế thư viện tại thời gian chạy.

#include <stdio.h>
#include <stdlib.h>
#include <dlfcn.h>
int x[2] = {1, 2};
int y[2] = {3, 4};
int z[2];
int main()
{
    void *handle;
    void (*addvec)(int *, int *, int *, int);
    char *error;
    /* Dynamically load the shared library that contains addvec() */
    handle = dlopen("./libvector.so", RTLD_LAZY);
    if (!handle) {
      fprintf(stderr, "%s\n", dlerror());
      exit(1);
    }
    ...
    /* Get a pointer to the addvec() function we just loaded */
    addvec = dlsym(handle, "addvec");
    if ((error = dlerror()) != NULL) {
      fprintf(stderr, "%s\n", error);
      exit(1);
    }
    /* Now we can call addvec() just like any other function */
    addvec(x, y, z, 2);
    printf("z = [%d %d]\n", z[0], z[1]);
    /* Unload the shared library */
    if (dlclose(handle) < 0) {
      fprintf(stderr, "%s\n", dlerror());
      exit(1);
    }
    return 0;
}

Tools to Manipulate Object Files

Công cụ để thao tác với tệp đối tượng

An object file contains a lot of information such as metadata, machine code, and other information from symbols. To manipulate such files, Unix provides certain tools to use them effectively, such as:

Một object chứa nhiều thông tin như siêu dữ liệu, machine code, và các thông tin khác từ symbols. Để thao tác với các tệp như vậy, Unix cung cấp một số công cụ để sử dụng chúng một cách hiệu quả, chẳng hạn như:

  • ar: Creates static libraries, and inserts, deletes, lists and extracts members.
  • ar: Tạo các thư viện tĩnh, và chèn, xóa, liệt kê và trích xuất các thành viên.
  • strings: Lists all the printable strings contained in an object file.
  • strings: Liệt kê tất cả các chuỗi có thể in được chứa trong một tệp đối tượng.
  • strip: Deletes symbol information from an object file.
  • strip: Xóa thông tin ký hiệu khỏi tệp đối tượng.
  • nm: Lists the symbols defined in the symbol table od an object file.
  • nm: Liệt kê các ký hiệu được định nghĩa trong bảng ký hiệu của một tệp đối tượng.
  • size: Lists the names and sizes of the sections in an object file.
  • kích thước: Liệt kê tên và kích thước của các phần trong một tệp đối tượng.
  • readelf: Displays the complete structure of an object file, including all of the information encoded in the ELF header; subsumes the functionality of “size” and “nm.”
  • readelf: Hiển thị cấu trúc hoàn chỉnh của một tệp đối tượng, bao gồm tất cả thông tin được mã hóa trong tiêu đề ELF; bao hàm chức năng của “size” và “nm.”
  • objdump: Displays all of the information in an object file; useful for disassembling binary instructions in the .text section.
  • objdump: Hiển thị tất cả thông tin trong một tệp đối tượng; hữu ích cho việc giải mã các lệnh nhị phân trong phần .text.
  • ldd (linux): Lists the shared libraries that an executable needs at runtime.
  • ldd (Linux): Liệt kê các thư viện chia sẻ mà một tệp thực thi cần trong thời gian chạy.

Version Control Management

Quản lý phiên bản

The process and tools used to store and improve multiple versions of project files is called version control. Version control also helps support team collaboration, and allows for the ability to revert to an earlier versions. Git is a widely-used version control system. Creating and updating project files using Git requires the creation of a Git repository, also known as “repo” for short. A repository is a container for files and related information stored in a version control tool. GitHub is a website that allows free storage of public git repositories.

Quá trình và công cụ được sử dụng để lưu trữ và cải thiện nhiều phiên bản của các tệp dự án được gọi là kiểm soát phiên bản. Kiểm soát phiên bản cũng giúp hỗ trợ sự hợp tác trong nhóm, và cho phép khả năng quay lại các phiên bản trước đó. Git là một hệ thống kiểm soát phiên bản được sử dụng rộng rãi. Việc tạo và cập nhật các tệp dự án bằng Git yêu cầu việc tạo ra một kho lưu trữ Git, còn được gọi tắt là “repo”. Một kho lưu trữ là một container cho các tệp và thông tin liên quan được lưu trữ trong một công cụ kiểm soát phiên bản. GitHub là một trang web cho phép lưu trữ miễn phí các kho lưu trữ git công khai.
