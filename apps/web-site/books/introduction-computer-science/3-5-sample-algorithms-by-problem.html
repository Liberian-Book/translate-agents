Earlier, we introduced several computing problems, like searching for a target value in a list or implementing an abstract data type (lists, sets, maps, priority queues, graphs). Although every computational problem is unique, these types of problems often share significant similarities with other problems. Computer scientists have identified many canonical problems that represent these common problem templates. Although each of these canonical problems may have many algorithmic solutions, computer scientists have also identified canonical algorithms for solving these problems. In this section, we will introduce canonical problems and survey canonical algorithms for each problem.

Trước đó, chúng ta đã giới thiệu một số vấn đề tính toán, như tìm kiếm một giá trị mục tiêu trong danh sách hoặc triển khai một kiểu dữ liệu trừu tượng (danh sách, tập hợp, bản đồ, hàng đợi ưu tiên, đồ thị). Mặc dù mỗi vấn đề tính toán là duy nhất, nhưng những loại vấn đề này thường chia sẻ những điểm tương đồng đáng kể với các vấn đề khác. Mặc dù mỗi vấn đề chuẩn mực này có thể có nhiều giải pháp thuật toán, các nhà khoa học máy tính cũng đã xác định các thuật toán chuẩn mực để giải quyết những vấn đề này. Trong phần này, chúng ta sẽ giới thiệu các vấn đề chuẩn mực và khảo sát các thuật toán chuẩn mực cho mỗi vấn đề.

Data Structure Problems

Vấn đề Cấu trúc Dữ liệu

Data structure problems are not only useful for implementing data structures, but also as fundamental algorithm design patterns for organizing data to enable efficient solutions to almost every other computing problem.

Các vấn đề về cấu trúc dữ liệu không chỉ hữu ích cho việc triển khai các cấu trúc dữ liệu, mà còn là các mẫu thiết kế thuật toán cơ bản để tổ chức dữ liệu nhằm cho phép giải quyết hiệu quả hầu hết mọi vấn đề tính toán khác.

Searching

Tìm kiếm

Searching is the problem of retrieving a target element from a collection of elements. Searching in a linear data structure, such as an array list, can be done using either sequential search or binary search.

Tìm kiếm là vấn đề lấy một target từ một tập hợp các phần tử. Tìm kiếm trong một cấu trúc dữ liệu tuyến tính, chẳng hạn như một array list, có thể được thực hiện bằng cách sử dụng sequential search hoặc binary search.

Sequential Search Algorithm
Thuật toán tìm kiếm tuần tự

A sequential search algorithm is a searching algorithm that sequentially checks the collection element-by-element for the target. The runtime of sequential search is in O(N) with respect to N, the number of elements in the list (Figure 3.22).

Một thuật toán tìm kiếm tuần tự là một thuật toán searching mà kiểm tra tuần tự từng phần tử trong tập hợp để tìm mục tiêu. Thời gian chạy của tìm kiếm tuần tự là O(N) liên quan đến N, số lượng phần tử trong danh sách (Hình 3.22).

Binary Search Algorithm
Thuật toán Tìm kiếm Nhị phân

A binary search algorithm recursively narrows down the possible locations for the target in the sorted list. Initially, the algorithm has no information—the target can be anywhere in the entire range of the sorted list. By comparing the target to the middle element of the range, we can rule-out half of the elements in the range. This process can be repeated until we have found the expected location of the target in the sorted list. The runtime of binary search is in O(log N) with respect to N, the number of elements in the sorted list, so long as indexing is a constant-time operation (see Figure 3.11).

Một binary search algorithm thu hẹp một cách đệ quy các vị trí khả thi cho mục tiêu trong danh sách đã được sắp xếp. Ban đầu, thuật toán không có thông tin nào—mục tiêu có thể ở bất kỳ đâu trong toàn bộ phạm vi của danh sách đã được sắp xếp. Bằng cách so sánh mục tiêu với phần tử ở giữa của phạm vi, chúng ta có thể loại bỏ một nửa số phần tử trong phạm vi. Quá trình này có thể được lặp lại cho đến khi chúng ta tìm thấy vị trí mong đợi của mục tiêu trong danh sách đã được sắp xếp. Thời gian runtime của binary search là O(log N) liên quan đến N, số lượng phần tử trong danh sách đã được sắp xếp, miễn là việc lập chỉ mục là một constant-time operation (xem Hình 3.11).

Although the sequential search algorithm works with any collection type such as lists, sets, dictionaries, and priority queues, the binary search algorithm relies on a sorted list with access to elements by index. Consequently, binary search is efficient on array lists that provide constant-time access to the element at any index and inefficient on linked lists, which do not enable constant-time access to elements by index. Binary search relies on the structure of the sorted list to repeatedly rule-out half of the remaining elements.

Mặc dù thuật toán tìm kiếm tuần tự hoạt động với bất kỳ loại bộ sưu tập nào như danh sách, tập hợp, từ điển và hàng đợi ưu tiên, thuật toán tìm kiếm nhị phân phụ thuộc vào một danh sách đã được sắp xếp với khả năng truy cập các phần tử theo index. Do đó, tìm kiếm nhị phân hiệu quả trên danh sách mảng cung cấp khả năng truy cập theo thời gian hằng số đến phần tử tại bất kỳ index nào và không hiệu quả trên danh sách liên kết, không cho phép truy cập theo thời gian hằng số đến các phần tử theo index. Tìm kiếm nhị phân dựa vào cấu trúc của danh sách đã được sắp xếp để liên tục loại bỏ một nửa số phần tử còn lại.

Binary search trees represent the concept of binary search in a tree data structure by arranging elements in the tree in sorted order from left to right. Ideally, the root node represents the middle element in the sorted tree and each child roughly divides each subtree in half. But, in the worst case, a binary search tree can look exactly like a linked list where each node contains either zero children or one child. Although such a tree still arranges its elements in sorted order from left to right, comparing the target to each node only reduces the size of the problem by one element rather than ruling out half of the remaining elements—the worst-case binary search tree degrades to sequential search. Balanced binary search trees, such as AVL trees, addressed this worst-case scenario by maintaining the AVL property of balance between left and right subtrees.

Cây tìm kiếm nhị phân đại diện cho khái niệm tìm kiếm nhị phân trong một cấu trúc dữ liệu cây bằng cách sắp xếp các phần tử trong cây theo thứ tự từ trái sang phải. Lý tưởng nhất, nút gốc đại diện cho phần tử ở giữa trong cây đã được sắp xếp và mỗi nút con chia mỗi cây con thành hai phần gần như bằng nhau. Tuy nhiên, trong trường hợp xấu nhất, một cây tìm kiếm nhị phân có thể trông giống hệt như một danh sách liên kết, nơi mỗi nút chứa hoặc không có nút con nào hoặc chỉ có một nút con. Mặc dù một cây như vậy vẫn sắp xếp các phần tử của nó theo thứ tự từ trái sang phải, việc so sánh mục tiêu với mỗi nút chỉ giảm kích thước của vấn đề xuống một phần tử thay vì loại bỏ một nửa các phần tử còn lại—cây tìm kiếm nhị phân trong trường hợp xấu nhất suy giảm thành tìm kiếm tuần tự. Các cây tìm kiếm nhị phân cân bằng, chẳng hạn như AVL trees, đã giải quyết tình huống xấu nhất này bằng cách duy trì thuộc tính cân bằng của AVL giữa các cây con bên trái và bên phải.

Sorting

Sắp xếp

Sorting is the problem of rearranging elements into a logical order, typically from least-valued (smallest) to greatest-valued (largest). Sorting is a fundamental problem not only because of the tasks that it directly solves, but also because it is a foundation for many other algorithms such as the binary search algorithm or Kruskal’s algorithm for the minimum spanning tree problem.

Sắp xếp là vấn đề sắp xếp lại các phần tử theo một thứ tự hợp lý, thường từ giá trị thấp nhất (nhỏ nhất) đến giá trị cao nhất (lớn nhất). Sắp xếp là một vấn đề cơ bản không chỉ vì những nhiệm vụ mà nó giải quyết trực tiếp, mà còn vì nó là nền tảng cho nhiều thuật toán khác như thuật toán tìm kiếm nhị phân hoặc Kruskal’s algorithm cho minimum spanning tree problem.

The most common type of sorting algorithm solves the problem of comparison sorting, or sorting a list of elements where elements are not assigned numeric values but rather defined in relation to other elements. For simplicity, the data are typically assumed to be stored in an array list for indexed access, and the sorting algorithm can either return a new sorted list or rearrange the elements in the array list so that they appear in sorted order.

Loại thuật toán sorting phổ biến nhất giải quyết vấn đề của comparison sorting, hoặc sắp xếp một danh sách các phần tử mà các phần tử không được gán giá trị số mà được định nghĩa theo mối quan hệ với các phần tử khác. Để đơn giản, dữ liệu thường được giả định là được lưu trữ trong một danh sách mảng để truy cập theo chỉ mục, và thuật toán sắp xếp có thể trả về một danh sách đã được sắp xếp mới hoặc sắp xếp lại các phần tử trong danh sách mảng sao cho chúng xuất hiện theo thứ tự đã sắp xếp.

Merge Sort Algorithm
Thuật toán Sắp xếp Hợp nhất

A merge sort algorithm recursively divides the data into sublists until sublists are one element long—which we know are sorted—and then merges adjacent sorted sublists to eventually return the sorted list. The merge operation combines two sorted sublists to produce a new, larger sorted sublist containing all the elements in sorted order. The actual rearranging of elements occurs by repeatedly applying the merge operation on pairs of adjacent sorted sublists, starting with the smallest single-element sublists, to larger two-element sublists, and eventually reaching the two halves of the entire list of elements. The runtime of merge sort is in O(N log N) with respect to N, the number of elements (see Figure 3.17).

Một merge sort algorithm chia nhỏ dữ liệu thành các danh sách con một cách đệ quy cho đến khi các danh sách con chỉ còn một phần tử—mà chúng ta biết là đã được sắp xếp—và sau đó hợp nhất các danh sách con đã được sắp xếp liền kề để cuối cùng trả về danh sách đã được sắp xếp. Phép hợp nhất kết hợp hai danh sách con đã được sắp xếp để tạo ra một danh sách con mới lớn hơn chứa tất cả các phần tử theo thứ tự đã được sắp xếp. Việc sắp xếp lại các phần tử thực sự diễn ra bằng cách áp dụng lặp đi lặp lại phép hợp nhất trên các cặp danh sách con đã được sắp xếp liền kề, bắt đầu với các danh sách con có một phần tử nhỏ nhất, đến các danh sách con có hai phần tử lớn hơn, và cuối cùng đạt đến hai nửa của toàn bộ danh sách các phần tử. Thời gian chạy của merge sort là O(N log N) liên quan đến N, số lượng phần tử (xem Hình 3.17).

Quicksort Algorithm
Thuật toán Quicksort

A quicksort algorithm recursively sorts data by applying the binary search tree algorithm design pattern to partition data around pivot elements. Whereas the merge sort algorithm rearranges elements by repeatedly merging sorted sublists after each recursive subproblem, the quicksort algorithm rearranges elements by partitioning data before each recursive subproblem. The partition operation takes a pivot and rearranges the elements into three sections, from left to right: the sublist of all elements less than the pivot, the pivot element, and the sublist of all elements greater than (or equal to) the pivot. Each of the two sublists resulting from the partition operation is a recursive quicksort subproblem; when both of the sublists are sorted, the entire list will be sorted. The runtime of quicksort depends on the choice of each pivot element during the execution of the recursive algorithm, but in practice, for most of the inputs, the runtime is in O(N log N) with respect to N, the number of elements (Figure 3.23).

Một thuật toán quicksort sắp xếp dữ liệu một cách đệ quy bằng cách áp dụng mẫu thiết kế thuật toán cây tìm kiếm nhị phân để phân vùng dữ liệu xung quanh các phần tử pivot. Trong khi thuật toán sắp xếp hợp nhất sắp xếp lại các phần tử bằng cách liên tục hợp nhất các danh sách con đã được sắp xếp sau mỗi bài toán con đệ quy, thuật toán quicksort sắp xếp lại các phần tử bằng cách phân vùng dữ liệu trước mỗi bài toán con đệ quy. Phép toán phân vùng lấy một pivot và sắp xếp lại các phần tử thành ba phần, từ trái sang phải: danh sách con của tất cả các phần tử nhỏ hơn pivot, phần tử pivot, và danh sách con của tất cả các phần tử lớn hơn (hoặc bằng) pivot. Mỗi trong hai danh sách con kết quả từ phép toán phân vùng là một bài toán con quicksort đệ quy; khi cả hai danh sách con được sắp xếp, toàn bộ danh sách sẽ được sắp xếp. Thời gian chạy của quicksort phụ thuộc vào việc chọn mỗi phần tử pivot trong quá trình thực thi thuật toán đệ quy, nhưng trên thực tế, đối với hầu hết các đầu vào, thời gian chạy là O(N log N) liên quan đến N, số lượng phần tử (Hình 3.23).

Heapsort Algorithm
Thuật toán Heapsort

A heapsort algorithm adds all elements to a binary heap priority queue data structure using the comparison operation to determine priority value, and returns the sorted list by repeatedly removing from the priority queue element by element. The runtime of heapsort is in O(N log N) with respect to N, the number of elements. The logarithmic time factor is due to the time it takes to add or remove each element from the binary heap (Figure 3.24).

Một thuật toán heapsort thêm tất cả các phần tử vào một cấu trúc dữ liệu priority queue dạng heap nhị phân bằng cách sử dụng so sánh để xác định giá trị ưu tiên, và trả về danh sách đã được sắp xếp bằng cách liên tục loại bỏ từng phần tử từ priority queue. Thời gian runtime của heapsort là O(N log N) liên quan đến N, số lượng phần tử. Yếu tố thời gian logarithmic là do thời gian cần thiết để thêm hoặc loại bỏ mỗi phần tử từ heap nhị phân (Hình 3.24).

Many comparison sorting algorithms share the same O(N log N) runtime bound with respect to N, the number of elements. Computer scientists have shown with a combinatorial proof that, in the worst case, a comparison sorting algorithm cannot do better than O(N log N) comparisons. It is impossible to design a worst-case O(N) runtime comparison sorting algorithm. In fact, a commonly used version of heapsort (which is also asymptotically faster) is to first build a binary heap (i.e., first arrange the input numbers in an array, then repeatedly call a function to turn the original array into a binary heap; one can show that the running time of this part is linear in N, which is why this is faster than constructing the heap by adding numbers one by one), then remove elements one by one from the end of the heap.

Nhiều thuật toán sắp xếp so sánh chia sẻ cùng một giới hạn thời gian O(N log N) liên quan đến N, số lượng phần tử. Các nhà khoa học máy tính đã chỉ ra bằng một chứng minh tổ hợp rằng, trong trường hợp xấu nhất, một thuật toán sắp xếp so sánh không thể làm tốt hơn O(N log N) so sánh. Không thể thiết kế một thuật toán sắp xếp so sánh có thời gian chạy O(N) trong trường hợp xấu nhất. Thực tế, một phiên bản thường được sử dụng của heapsort (cũng nhanh hơn về mặt tiệm cận) là trước tiên xây dựng một heap nhị phân (tức là, trước tiên sắp xếp các số đầu vào trong một mảng, sau đó gọi liên tục một hàm để biến đổi mảng gốc thành một heap nhị phân; có thể chỉ ra rằng thời gian chạy của phần này là tuyến tính trong N, đó là lý do tại sao điều này nhanh hơn so với việc xây dựng heap bằng cách thêm số một cách lần lượt), sau đó loại bỏ các phần tử một cách lần lượt từ cuối heap.

But not all sorting problems are comparison sorting problems. In fact, a commonly used version of heapsort (which is also asymptotically faster) is to first build a binary heap (i.e., first arrange the input numbers in an array, then repeatedly call a function to turn the original array into a binary heap. One can show that the running time of this part is linear in N, which is why this is faster than constructing the heap by adding numbers one by one), then remove elements one by one from the end of the heap as explained previously.

Nhưng không phải tất cả các bài toán sắp xếp đều là bài toán sắp xếp so sánh. Thực tế, một phiên bản thường được sử dụng của heapsort (cũng nhanh hơn về mặt tiệm cận) là trước tiên xây dựng một heap nhị phân (tức là, trước tiên sắp xếp các số đầu vào trong một mảng, sau đó gọi liên tục một hàm để biến đổi mảng gốc thành một heap nhị phân. Có thể chỉ ra rằng thời gian chạy của phần này là tuyến tính trong N, đó là lý do tại sao nó nhanh hơn so với việc xây dựng heap bằng cách thêm các số một cách lần lượt), sau đó loại bỏ các phần tử một cách lần lượt từ cuối heap như đã giải thích trước đó.

Another type of sorting problem that is not restricted to pairwise comparisons is known as count sorting, or sorting a list of elements by organizing elements into categories and rearranging the categories into a logical order. For example, the problem of sorting a deck of cards can be seen as a count sorting problem if we put the cards into numeric stacks and then rearrange the stacks into a logical order. By changing the assumptions of the problem, count sorting algorithms can run in O(N) time by first assigning each element to its respective category and then unpacking each category so that elements appear in sorted order.

Một loại vấn đề sắp xếp khác không bị giới hạn bởi các so sánh cặp là được biết đến với tên gọi sắp xếp theo số lượng, hoặc sắp xếp một danh sách các phần tử bằng cách tổ chức các phần tử thành các loại và sắp xếp lại các loại theo một thứ tự hợp lý. Ví dụ, vấn đề sắp xếp một bộ bài có thể được coi là một vấn đề sắp xếp theo số lượng nếu chúng ta đặt các lá bài vào các chồng số và sau đó sắp xếp lại các chồng theo một thứ tự hợp lý. Bằng cách thay đổi các giả định của vấn đề, các thuật toán sắp xếp theo số lượng có thể chạy trong thời gian O(N) bằng cách đầu tiên gán mỗi phần tử vào loại tương ứng của nó và sau đó giải nén mỗi loại để các phần tử xuất hiện theo thứ tự đã sắp xếp.

Hashing

Băm

Hashing is the problem of designing efficient algorithms which map each object to an integer so that most (if not all) objects will be assigned distinct integers. Although hashing algorithms are often specific to each data type, there exist some general approaches for designing hashing algorithms. The hash value of a simple data type such as an integer can just be the value of the integer itself. The hash value of a string of text can be some mathematical combination of the numeric value of each character in the string. Likewise, the hash value of a collection such as a list can be some combination of the underlying numeric data within each element in the collection.

Hashing là vấn đề thiết kế các thuật toán hiệu quả mà ánh xạ mỗi đối tượng thành một số nguyên sao cho hầu hết (nếu không muốn nói là tất cả) các đối tượng sẽ được gán các số nguyên khác nhau. Mặc dù hashing thường cụ thể cho từng loại dữ liệu, nhưng vẫn tồn tại một số phương pháp chung để thiết kế các thuật toán hashing. Giá trị hash của một kiểu dữ liệu đơn giản như số nguyên có thể chỉ là giá trị của chính số nguyên đó. Giá trị hash của một chuỗi văn bản có thể là một sự kết hợp toán học của giá trị số của mỗi ký tự trong chuỗi. Tương tự, giá trị hash của một tập hợp như danh sách có thể là một sự kết hợp của dữ liệu số cơ bản trong mỗi phần tử của tập hợp.

Hashing has a variety of applications spanning computer systems, database systems, computer security, and searching algorithms. For example, hashing algorithms are often used designing secure systems for protecting stored passwords even after a security breach occurs. In the context of data structure problems, hashing offers a different approach than binary search. Instead of relying on pairwise comparisons to narrow down the expected location of an element in a sorted list in logarithmic time, hashing search algorithms can instead directly index an element by hash value in constant time. If binary search trees implement sets and maps by applying the concept of binary search, a hash table implements sets and maps by applying the concept of hashing (Figure 3.25). Rather than organize elements in sorted order from left to right as in a binary search tree, hash tables store and retrieve elements in an array indexed by hash value.

Hashing có nhiều ứng dụng trong các hệ thống máy tính, hệ thống cơ sở dữ liệu, an ninh máy tính và thuật toán tìm kiếm. Ví dụ, các thuật toán hashing thường được sử dụng để thiết kế các hệ thống an toàn nhằm bảo vệ mật khẩu đã lưu ngay cả sau khi xảy ra vi phạm an ninh. Trong bối cảnh các vấn đề cấu trúc dữ liệu, hashing cung cấp một cách tiếp cận khác so với tìm kiếm nhị phân. Thay vì dựa vào các so sánh cặp để thu hẹp vị trí dự kiến của một phần tử trong danh sách đã sắp xếp trong thời gian logarithmic, các thuật toán tìm kiếm hashing có thể trực tiếp lập chỉ mục một phần tử theo giá trị hash trong thời gian không đổi. Nếu cây tìm kiếm nhị phân triển khai các tập hợp và bản đồ bằng cách áp dụng khái niệm tìm kiếm nhị phân, một bảng hash triển khai các tập hợp và bản đồ bằng cách áp dụng khái niệm hashing (Hình 3.25). Thay vì tổ chức các phần tử theo thứ tự đã sắp xếp từ trái sang phải như trong một cây tìm kiếm nhị phân, các bảng hash lưu trữ và truy xuất các phần tử trong một mảng được lập chỉ mục theo giá trị hash.

Hashing search algorithms are often preferred over binary search algorithms for their runtime benefits, but they come with unique drawbacks. Ideally, different objects would hash to different hash values. But the combinatorial explosion of possibilities for unique strings or collections of complex data means that a collision, or a situation in which multiple objects hash to the same integer index value, is inevitable since integers in a computer can typically only represent a certain, fixed range of integer numbers. Combinatorial explosion is not only a problem for the design of efficient algorithms, but also the design of efficient data structures too.

Các thuật toán tìm kiếm bằng băm thường được ưa chuộng hơn so với các thuật toán tìm kiếm nhị phân vì lợi ích về thời gian chạy của chúng, nhưng chúng cũng đi kèm với những nhược điểm riêng. Lý tưởng nhất, các đối tượng khác nhau sẽ băm ra các giá trị băm khác nhau. Nhưng sự bùng nổ tổ hợp của các khả năng cho các chuỗi duy nhất hoặc các tập hợp dữ liệu phức tạp có nghĩa là một collision, hoặc một tình huống trong đó nhiều đối tượng băm ra cùng một giá trị chỉ số nguyên, là điều không thể tránh khỏi vì các số nguyên trong máy tính thường chỉ có thể đại diện cho một phạm vi số nguyên nhất định và cố định. Sự bùng nổ tổ hợp không chỉ là một vấn đề cho việc thiết kế các thuật toán hiệu quả, mà còn cho việc thiết kế các cấu trúc dữ liệu hiệu quả nữa.

Graph Problems

Vấn đề đồ thị

While data structure problems focus primarily on storage and retrieval of elements in a collection, graph problems include a wide variety of computing problems involving the graph data structure. Unlike other data structures, graphs include not only elements (vertices) but also relationships between elements (edges). Graph problems often ask algorithm designers to explore the graph in order to answer questions about elements and the relationships between elements.

Trong khi các bài toán cấu trúc dữ liệu chủ yếu tập trung vào việc lưu trữ và truy xuất các phần tử trong một tập hợp, graph problem bao gồm nhiều loại bài toán tính toán liên quan đến cấu trúc dữ liệu đồ thị. Khác với các cấu trúc dữ liệu khác, đồ thị không chỉ bao gồm các phần tử (đỉnh) mà còn cả các mối quan hệ giữa các phần tử (cạnh). Các bài toán đồ thị thường yêu cầu các nhà thiết kế thuật toán khám phá đồ thị để trả lời các câu hỏi về các phần tử và các mối quan hệ giữa các phần tử.

Traversal

Duyệt qua

Traversal is the problem of exploring all the vertices in a graph. Graph data structures differ from tree data structures in that there is no explicit root node to begin the traversal and edges can connect back to other parts of the graph. In general, there is no guarantee of hierarchy in a graph. Graph traversal algorithms such as depth-first search and breadth-first search begin at an arbitrary start vertex and explore outwards from the start vertex while keeping track of a set of explored vertices.

Traversal là vấn đề khám phá tất cả các đỉnh trong một đồ thị. Các cấu trúc dữ liệu đồ thị khác với các cấu trúc dữ liệu cây ở chỗ không có nút gốc rõ ràng để bắt đầu traversal và các cạnh có thể kết nối trở lại các phần khác của đồ thị. Nói chung, không có đảm bảo về thứ bậc trong một đồ thị. Các thuật toán duyệt đồ thị như tìm kiếm theo chiều sâu và tìm kiếm theo chiều rộng bắt đầu từ một đỉnh khởi đầu tùy ý và khám phá ra ngoài từ đỉnh khởi đầu trong khi theo dõi một tập hợp các đỉnh đã được khám phá.

Depth-First Search
Tìm kiếm theo chiều sâu

A depth-first search is a graph traversal algorithm that recursively explores each neighbor, continuing as far possible along each subproblem depth-first (Figure 3.26). Explored vertices are added to a global set to ensure that the algorithm only explores each vertex once. The runtime of depth-first search is in O(|V| + |E|) with respect to |V|, the number of vertices, and |E|, the number of edges.

Một tìm kiếm theo chiều sâu là một thuật toán duyệt đồ thị mà khám phá đệ quy từng hàng xóm, tiếp tục càng xa càng tốt dọc theo mỗi bài toán con theo chiều sâu (Hình 3.26). Các đỉnh đã được khám phá được thêm vào một tập toàn cục để đảm bảo rằng thuật toán chỉ khám phá mỗi đỉnh một lần. Thời gian chạy của tìm kiếm theo chiều sâu là O(|V| + |E|) liên quan đến |V|, số lượng đỉnh, và |E|, số lượng cạnh.

Breadth-First Search
Tìm kiếm theo chiều rộng

A breadth-first search iteratively explores each neighbor, expanding the search level-by-level breadth-first (Figure 3.27). Explored vertices are also added to a global set to ensure that the algorithm explores each vertex once and in the correct level-order. The runtime of breadth-first search is also in O(|V| + |E|) with respect to |V|, the number of vertices, and |E|, the number of edges.

Một tìm kiếm theo chiều rộng sẽ khám phá từng hàng xóm một cách lặp đi lặp lại, mở rộng tìm kiếm theo từng cấp độ theo chiều rộng (Hình 3.27). Các đỉnh đã được khám phá cũng được thêm vào một tập hợp toàn cầu để đảm bảo rằng thuật toán khám phá mỗi đỉnh một lần và theo thứ tự cấp độ chính xác. Thời gian runtime của tìm kiếm theo chiều rộng cũng nằm trong O(|V| + |E|) liên quan đến |V|, số lượng đỉnh, và |E|, số lượng cạnh.

Graph traversal algorithms are the foundational algorithm design patterns for most graph processing algorithms. Many algorithms require some amount of exploration, and that exploration typically starts at some vertex and continues processing each reachable vertex at most once. A reachable vertex can be reached if a path or sequence of edges from the start vertex exists. As opposed to depth-first search, breadth-first search has the benefit of exploring vertices closer to the start before exploring vertices further from the start, which can be useful for solving problems such as unweighted shortest paths.

Các thuật toán duyệt đồ thị là các mẫu thiết kế thuật toán cơ bản cho hầu hết các thuật toán xử lý đồ thị. Nhiều thuật toán yêu cầu một lượng khám phá nào đó, và việc khám phá đó thường bắt đầu từ một đỉnh nào đó và tiếp tục xử lý mỗi đỉnh có thể tiếp cận được tối đa một lần. Một đỉnh có thể tiếp cận có thể được tiếp cận nếu tồn tại một đường đi hoặc chuỗi các cạnh từ đỉnh bắt đầu. Khác với tìm kiếm theo chiều sâu, tìm kiếm theo chiều rộng có lợi thế là khám phá các đỉnh gần hơn với điểm bắt đầu trước khi khám phá các đỉnh xa hơn, điều này có thể hữu ích cho việc giải quyết các vấn đề như đường đi ngắn nhất không trọng số.

Minimum Spanning Trees

Cây bao trùm tối thiểu

Minimum spanning trees is the problem of finding a lowest-cost way to connect all the vertices to each other, where cost is the sum of the selected edge weights. The two canonical greedy algorithms for finding a minimum spanning tree in a graph are Kruskal’s algorithm and Prim’s algorithm. Both algorithms repeatedly apply the rule of selecting the next lowest-weight edge to an unconnected part of the graph. The output of a minimum spanning tree algorithm is a set of |V| - 1 edges connecting all the vertices in the graph with the least total sum of edge weights, where |V| is the number of vertices.

Cây khung tối thiểu là bài toán tìm cách kết nối tất cả các đỉnh với nhau với chi phí thấp nhất, trong đó cost là tổng trọng số của các cạnh được chọn. Hai thuật toán greedy algorithm điển hình để tìm minimum spanning tree trong một đồ thị là Kruskal’s algorithm và Prim’s algorithm. Cả hai thuật toán đều lặp đi lặp lại quy tắc chọn cạnh có trọng số thấp nhất tiếp theo cho một phần chưa kết nối của đồ thị. Đầu ra của một thuật toán cây khung tối thiểu là một tập hợp |V| - 1 cạnh kết nối tất cả các đỉnh trong đồ thị với tổng trọng số cạnh thấp nhất, trong đó |V| là số lượng đỉnh.

Kruskal’s Algorithm
Thuật toán Kruskal

Kruskal’s algorithm begins by considering each vertex as an independent "island," and the goal of the algorithm is to repeatedly connect islands by selecting the lowest-cost edges. A specialized data structure (called disjoint sets) is typically used to keep track of the independent islands. The runtime of Kruskal’s algorithm is in O(|E| log |E|) with respect to |E|, the number of edges (Figure 3.28).

Thuật toán Kruskal bắt đầu bằng cách xem xét mỗi đỉnh như một "hòn đảo" độc lập, và mục tiêu của thuật toán là liên tục kết nối các hòn đảo bằng cách chọn các cạnh có chi phí thấp nhất. Một cấu trúc dữ liệu chuyên biệt (gọi là tập hợp không giao nhau) thường được sử dụng để theo dõi các hòn đảo độc lập. Thời gian thực thi của thuật toán Kruskal là O(|E| log |E|) liên quan đến |E|, số lượng cạnh (Hình 3.28).

Prim’s Algorithm
Thuật toán Prim

Prim’s algorithm grows a minimum spanning tree one edge at a time by selecting the lowest-weight edge to an unexplored vertex. The runtime of Prim’s algorithm is in O(|E| log |V| + |V| log |V|) with respect to |V|, the number of vertices, and |E|, the number of edges (Figure 3.29).

Thuật toán Prim phát triển một cây khung tối thiểu từng cạnh một bằng cách chọn cạnh có trọng số thấp nhất đến một đỉnh chưa được khám phá. Thời gian thực thi của thuật toán Prim là O(|E| log |V| + |V| log |V|) liên quan đến |V|, số lượng đỉnh, và |E|, số lượng cạnh (Hình 3.29).

Shortest Paths

Đường đi ngắn nhất

The output of a shortest paths algorithm is a shortest paths tree, the lowest-cost way to get from one vertex to every other vertex in a graph (Figure 3.30). The unweighted shortest path is the problem of finding the shortest paths in terms of the number of edges. Given a start vertex, breadth-first search can compute the unweighted shortest paths tree from the start vertex to every other reachable vertex in the graph by maintaining a map data structure of the path used to reach each vertex.

Đầu ra của một thuật toán shortest paths là một shortest paths tree, cách có chi phí thấp nhất để đi từ một đỉnh đến mọi đỉnh khác trong đồ thị (Hình 3.30). unweighted shortest path là bài toán tìm các đường đi ngắn nhất theo số lượng cạnh. Với một đỉnh bắt đầu, tìm kiếm theo chiều rộng có thể tính toán cây shortest paths không trọng số từ đỉnh bắt đầu đến mọi đỉnh có thể tiếp cận khác trong đồ thị bằng cách duy trì một cấu trúc dữ liệu bản đồ của đường đi đã sử dụng để đến mỗi đỉnh.

Weighted Shortest Path
Đường đi ngắn nhất có trọng số

A weighted shortest path is the problem of finding the shortest paths in terms of the sum of the edge weights. Earlier, we introduced Prim’s algorithm, a minimum spanning tree algorithm that maintains a priority queue of edges in the graph ordered by weight and repeatedly selects the next lowest-cost edge to an unconnected part of the graph.

Một đường đi ngắn nhất có trọng số là bài toán tìm các đường đi ngắn nhất dựa trên tổng trọng số của các cạnh. Trước đó, chúng ta đã giới thiệu thuật toán Prim, một thuật toán cây bao trùm tối thiểu duy trì một hàng đợi ưu tiên các cạnh trong đồ thị được sắp xếp theo trọng số và liên tục chọn cạnh có chi phí thấp nhất tiếp theo đến một phần chưa kết nối của đồ thị.

Weighted Shortest Paths for Navigation Directions

Đường đi ngắn nhất có trọng số cho chỉ dẫn điều hướng

One of the most direct applications of the shortest paths problem is to provide recommended routes for navigation directions in real-world mapping. Many applications use distance as the metric for edge weight, so the shortest path between two points represents the real-world route with the smallest distance between the two places.

Một trong những ứng dụng trực tiếp nhất của bài toán đường đi ngắn nhất là cung cấp các tuyến đường được đề xuất cho chỉ dẫn điều hướng trong bản đồ thế giới thực. Nhiều ứng dụng sử dụng khoảng cách làm thước đo cho trọng số cạnh, vì vậy đường đi ngắn nhất giữa hai điểm đại diện cho tuyến đường trong thế giới thực có khoảng cách nhỏ nhất giữa hai địa điểm.

What does a distance metric not consider when providing a recommended route? What values are centered and emphasized by even using a shortest paths algorithm for recommending routes?

Một chỉ số khoảng cách không xem xét điều gì khi cung cấp một lộ trình được đề xuất? Những giá trị nào được tập trung và nhấn mạnh ngay cả khi sử dụng thuật toán đường đi ngắn nhất để đề xuất lộ trình?

Dijkstra’s Algorithm
Thuật toán Dijkstra

Dijkstra’s algorithm maintains a priority queue of vertices in the graph ordered by distance from the start and repeatedly selects the next shortest path to an unconnected part of the graph. Dijkstra’s algorithm is almost identical to Prim’s algorithm except processing shortest paths (sequences of edges) rather than individual edges. Dijkstra’s algorithm grows a shortest paths tree one shortest path at a time by selecting the next shortest path to an unexplored vertex. The runtime of Dijkstra’s algorithm is in O(|E| log |V| + |V| log |V|) with respect to |V|, the number of vertices, and |E|, the number of edges (Figure 3.31).

Thuật toán Dijkstra duy trì một hàng đợi ưu tiên các đỉnh trong đồ thị được sắp xếp theo khoảng cách từ điểm bắt đầu và lặp đi lặp lại chọn đường đi ngắn nhất tiếp theo đến một phần chưa kết nối của đồ thị. Thuật toán Dijkstra gần như giống hệt với thuật toán Prim ngoại trừ việc xử lý các đường đi ngắn nhất (chuỗi các cạnh) thay vì các cạnh riêng lẻ. Thuật toán Dijkstra phát triển một shortest paths tree từng đường đi ngắn nhất một lần bằng cách chọn đường đi ngắn nhất tiếp theo đến một đỉnh chưa được khám phá. Thời gian chạy của thuật toán Dijkstra là O(|E| log |V| + |V| log |V|) liên quan đến |V|, số lượng đỉnh, và |E|, số lượng cạnh (Hình 3.31).
