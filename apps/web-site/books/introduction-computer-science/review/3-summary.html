3.1 Introduction to Data Structures and Algorithms

3.1 Giới thiệu về Cấu trúc Dữ liệu và Thuật toán
  • Data structures represent complex data types for solving real-world problems. Data structures combine specific data representations with specific functionality.
  • Cấu trúc dữ liệu đại diện cho các kiểu dữ liệu phức tạp để giải quyết các vấn đề trong thế giới thực. Cấu trúc dữ liệu kết hợp các biểu diễn dữ liệu cụ thể với các chức năng cụ thể.
  • Abstract data types categorize data structures according to their functionality and ignore differences in data representation. Abstract data types include lists, sets, maps, priority queues, and graphs.
  • Các kiểu dữ liệu trừu tượng phân loại các cấu trúc dữ liệu theo chức năng của chúng và bỏ qua sự khác biệt trong cách biểu diễn dữ liệu. Các kiểu dữ liệu trừu tượng bao gồm danh sách, tập hợp, bản đồ, hàng đợi ưu tiên và đồ thị.
  • To select an appropriate data structure, first select an abstract data type according to the problem requirements. Then, select an appropriate data structure implementation for the abstract data type.
  • Để chọn một cấu trúc dữ liệu phù hợp, trước tiên hãy chọn một kiểu dữ liệu trừu tượng theo yêu cầu của vấn đề. Sau đó, hãy chọn một triển khai cấu trúc dữ liệu phù hợp cho kiểu dữ liệu trừu tượng.
  • Linear data structures organize elements in a line, ideal for implementing the list abstract data type. Linear data structures include array lists and linked lists.
  • Cấu trúc dữ liệu tuyến tính tổ chức các phần tử theo một dòng, lý tưởng cho việc triển khai kiểu dữ liệu trừu tượng danh sách. Cấu trúc dữ liệu tuyến tính bao gồm danh sách mảng và danh sách liên kết.
  • Linear data structures can implement any abstract data type. The study of data structures in general focuses on opportunities to improve efficiency (in terms of execution time or memory usage) over linear data structures.
  • Cấu trúc dữ liệu tuyến tính có thể triển khai bất kỳ kiểu dữ liệu trừu tượng nào. Nghiên cứu về cấu trúc dữ liệu nói chung tập trung vào các cơ hội để cải thiện hiệu suất (về thời gian thực thi hoặc mức sử dụng bộ nhớ) so với các cấu trúc dữ liệu tuyến tính.
  • Tree data structures organize elements in a hierarchy of levels defined by parent-child relationships. Trees are defined with a root node at the top of the tree, parent-child relationships between each level, and leaf nodes at the bottom of the tree.
  • Cấu trúc dữ liệu cây tổ chức các phần tử trong một hệ thống phân cấp các cấp độ được xác định bởi mối quan hệ cha-con. Cây được định nghĩa với một nút gốc ở đỉnh cây, các mối quan hệ cha-con giữa mỗi cấp độ, và các nút lá ở đáy cây.
  • Binary search trees require that elements in the tree are organized least-to-greatest from left-to-right. Binary search trees are often used to implement the set and map abstract data types.
  • Cây tìm kiếm nhị phân yêu cầu rằng các phần tử trong cây được sắp xếp từ nhỏ đến lớn từ trái sang phải. Cây tìm kiếm nhị phân thường được sử dụng để triển khai các kiểu dữ liệu trừu tượng tập hợp và bản đồ.
  • Balanced binary search trees and binary heaps represent two approaches for avoiding the worst-case situation with binary search trees. Binary heaps are often used to implement the priority queue abstract data type.
  • Cây tìm kiếm nhị phân cân bằng và đống nhị phân đại diện cho hai cách tiếp cận để tránh tình huống xấu nhất với cây tìm kiếm nhị phân. Đống nhị phân thường được sử dụng để triển khai kiểu dữ liệu trừu tượng hàng đợi ưu tiên.
  • Graph data structures focus on explicitly modeling the relationships between elements. Graphs afford access not only to elements, but also to the relationships between elements.
  • Cấu trúc dữ liệu đồ thị tập trung vào việc mô hình hóa rõ ràng các mối quan hệ giữa các phần tử. Đồ thị không chỉ cung cấp quyền truy cập vào các phần tử, mà còn vào các mối quan hệ giữa các phần tử.

3.2 Algorithm Design and Discovery

3.2 Thiết kế và Khám phá Thuật toán
  • Just like how many data structures can represent the same abstract data type, many algorithms exist to solve the same problem. In algorithmic problem-solving, computer scientists solve formal problems with specific input data and output data that correspond to each input.
  • Cũng giống như nhiều cấu trúc dữ liệu có thể đại diện cho cùng một kiểu dữ liệu trừu tượng, có nhiều thuật toán tồn tại để giải quyết cùng một vấn đề. Trong việc giải quyết vấn đề thuật toán, các nhà khoa học máy tính giải quyết các vấn đề chính thức với dữ liệu đầu vào cụ thể và dữ liệu đầu ra tương ứng với mỗi đầu vào.
  • Modeling is the process of representing a complex phenomenon such as a real-world problem as a formal problem. Modeling is about abstraction: the simplification or erasure of details so that the problem can be solved by a computer.
  • Mô hình hóa là quá trình đại diện cho một hiện tượng phức tạp như một vấn đề trong thế giới thực dưới dạng một vấn đề chính thức. Mô hình hóa liên quan đến sự trừu tượng: việc đơn giản hóa hoặc xóa bỏ các chi tiết để vấn đề có thể được giải quyết bởi một máy tính.
  • Historically, the model of computation emphasized specialized algorithms operating on a modest model of the underlying phenomenon. Modeling is a violent but also necessary act in order to simplify the problem so that it can be solved by a computer.
  • Lịch sử cho thấy, mô hình tính toán nhấn mạnh các thuật toán chuyên biệt hoạt động trên một mô hình khiêm tốn của hiện tượng cơ bản. Mô hình hóa là một hành động bạo lực nhưng cũng cần thiết để đơn giản hóa vấn đề sao cho nó có thể được giải quyết bởi một máy tính.
  • Searching is the problem of retrieving a target element from a collection of many elements. Sequential search and binary search are two algorithms for solving the search problem.
  • Tìm kiếm là vấn đề lấy một phần tử mục tiêu từ một tập hợp nhiều phần tử. Tìm kiếm tuần tự và tìm kiếm nhị phân là hai thuật toán để giải quyết vấn đề tìm kiếm.
  • To solve real-world problems, computer scientists compose, modify, and apply algorithm design patterns, such as search algorithms.
  • Để giải quyết các vấn đề trong thế giới thực, các nhà khoa học máy tính soạn thảo, sửa đổi và áp dụng các mẫu thiết kế thuật toán, chẳng hạn như các thuật toán tìm kiếm.
  • Algorithm analysis is the study of the outputs produced by an algorithm as well as how the algorithm produces those outputs.
  • Phân tích thuật toán là nghiên cứu các đầu ra được tạo ra bởi một thuật toán cũng như cách mà thuật toán tạo ra những đầu ra đó.
  • Correctness considers whether the outputs produced by an algorithm match the expected or desired results across the range of possible inputs. Correctness is defined as a match between the algorithm and the model of the problem, not between the algorithm and the real-world.
  • Độ chính xác xem xét liệu các đầu ra được tạo ra bởi một thuật toán có khớp với kết quả mong đợi hoặc mong muốn trong toàn bộ phạm vi các đầu vào có thể có hay không. Độ chính xác được định nghĩa là sự khớp nhau giữa thuật toán và mô hình của vấn đề, chứ không phải giữa thuật toán và thế giới thực.
  • Correctness is complicated by the complexity of social relationships, power, and inequity in the real-world. Since algorithms automate processes and operate in existing power structures, they are likely to reproduce and amplify social injustice.
  • Độ chính xác trở nên phức tạp bởi sự phức tạp của các mối quan hệ xã hội, quyền lực và sự bất bình đẳng trong thế giới thực. Bởi vì các thuật toán tự động hóa các quy trình và hoạt động trong các cấu trúc quyền lực hiện có, chúng có khả năng tái sản xuất và khuếch đại sự bất công xã hội.
  • In addition to correctness, computer scientists are also interested in complexity, or measuring the computational resources that an algorithm consumes during its execution in relation to the size of the input.
  • Ngoài độ chính xác, các nhà khoa học máy tính cũng quan tâm đến độ phức tạp, hay việc đo lường các tài nguyên tính toán mà một thuật toán tiêu tốn trong quá trình thực thi liên quan đến kích thước của đầu vào.

3.3 Formal Properties of Algorithms

3.3 Các Tính Chất Chính Thức của Thuật Toán
  • Runtime analysis is a study of how much time it takes to run an algorithm. Experimental analysis is a runtime analysis technique that involves evaluating an algorithm’s runtime by recording how long it takes to run a program implementation of it.
  • Phân tích thời gian chạy là một nghiên cứu về thời gian cần thiết để thực hiện một thuật toán. Phân tích thực nghiệm là một kỹ thuật phân tích thời gian chạy liên quan đến việc đánh giá thời gian chạy của một thuật toán bằng cách ghi lại thời gian cần thiết để thực hiện một chương trình cài đặt của nó.
  • Time complexity is the formal measure of how much time an algorithm requires during execution as it relates to the size of the problem. The goal of time complexity analysis is to produce a simple and easy-to-compare characterization of the runtime of an algorithm as it relates to the size of the problem.
  • Độ phức tạp thời gian là thước đo chính thức về thời gian mà một thuật toán yêu cầu trong quá trình thực thi liên quan đến kích thước của vấn đề. Mục tiêu của phân tích độ phức tạp thời gian là tạo ra một đặc trưng đơn giản và dễ so sánh về thời gian chạy của một thuật toán liên quan đến kích thước của vấn đề.
  • Space complexity is the formal measure of how much memory an algorithm requires during execution as it relates to the size of the problem.
  • Độ phức tạp không gian là thước đo chính thức về lượng bộ nhớ mà một thuật toán yêu cầu trong quá trình thực thi liên quan đến kích thước của vấn đề.
  • Steps in time complexity analysis are to identify a metric for representing the size of the problem; to model the number of steps needed to execute the algorithm; and to formalize the model using either precise English or asymptotic notation to define the order of growth. Big O notation is the most common type of asymptotic notation in computer science.
  • Các bước trong phân tích độ phức tạp thời gian là xác định một chỉ số để đại diện cho kích thước của vấn đề; mô hình hóa số bước cần thiết để thực hiện thuật toán; và chính thức hóa mô hình bằng cách sử dụng tiếng Anh chính xác hoặc ký hiệu tiệm cận để xác định thứ tự tăng trưởng. Ký hiệu Big O là loại ký hiệu tiệm cận phổ biến nhất trong khoa học máy tính.
  • Differences in orders of growth are massive: as the input size grows, the difference between orders of growth becomes more and more vast. For problems dealing with just 1,000 elements, the time it would take to run an exponential-time algorithm on that problem exceeds the current age of the universe—whereas that same-size problem running on the same computer would take just 1 second on a quadratic-time algorithm.
  • Sự khác biệt trong các bậc tăng trưởng là rất lớn: khi kích thước đầu vào tăng lên, sự khác biệt giữa các bậc tăng trưởng trở nên ngày càng rộng lớn hơn. Đối với các bài toán liên quan đến chỉ 1.000 phần tử, thời gian cần thiết để chạy một thuật toán có thời gian hàm mũ trên bài toán đó vượt quá tuổi thọ hiện tại của vũ trụ—trong khi bài toán cùng kích thước đó chạy trên cùng một máy tính chỉ mất 1 giây với một thuật toán có thời gian bậc hai.
  • In practice, across applications working with large amounts of data, O(N2) is often considered the limit for real-world algorithms. For algorithms that need to run frequently on large amounts of data, algorithm designers target O(N), O(log N), or O(1).
  • Trong thực tế, trong các ứng dụng làm việc với một lượng lớn dữ liệu, O(N2) thường được coi là giới hạn cho các thuật toán trong thế giới thực. Đối với các thuật toán cần chạy thường xuyên trên một lượng lớn dữ liệu, các nhà thiết kế thuật toán nhắm đến O(N), O(log N), hoặc O(1).

3.4 Algorithmic Paradigms

3.4 Các Mô Hình Thuật Toán
  • Algorithmic paradigms are the common concepts and ideas behind algorithm design patterns, such as divide and conquer algorithms, brute-force algorithms, greedy algorithms, and reduction algorithms.
  • Các mô hình thuật toán là những khái niệm và ý tưởng chung đứng sau các mẫu thiết kế thuật toán, chẳng hạn như thuật toán chia và chinh phục, thuật toán brute-force, thuật toán tham lam và thuật toán giảm thiểu.
  • Divide and conquer algorithms break down a problem into smaller subproblems (divide), recursively solve each subproblem (conquer), and then combine the result of each subproblem to inform the overall solution. Recursion is an algorithm idea fundamental to divide and conquer algorithms that solves complex problems by dividing input data into smaller, independent instances of the same problem known as subproblems.
  • Các thuật toán chia để trị phân tách một vấn đề thành các tiểu vấn đề nhỏ hơn (chia), giải quyết đệ quy từng tiểu vấn đề (trị), và sau đó kết hợp kết quả của từng tiểu vấn đề để thông báo cho giải pháp tổng thể. Đệ quy là một ý tưởng thuật toán cơ bản đối với các thuật toán chia để trị, giải quyết các vấn đề phức tạp bằng cách chia dữ liệu đầu vào thành các trường hợp nhỏ hơn, độc lập của cùng một vấn đề được gọi là tiểu vấn đề.
  • Binary search is an example of divide and conquer algorithm with a single recursive subproblem. Merge sort is an example of a divide and conquer algorithm with two recursive subproblems.
  • Tìm kiếm nhị phân là một ví dụ về thuật toán chia để trị với một bài toán con đệ quy duy nhất. Sắp xếp hợp nhất là một ví dụ về thuật toán chia để trị với hai bài toán con đệ quy.
  • Brute-force algorithms solve combinatorial problems by systematically enumerating all potential solutions in order to identify the best candidate solution. Combinatorial problems identify the best candidate solution out of a space of many potential solutions.
  • Các thuật toán brute-force giải quyết các vấn đề tổ hợp bằng cách liệt kê một cách có hệ thống tất cả các giải pháp tiềm năng để xác định giải pháp ứng viên tốt nhất. Các vấn đề tổ hợp xác định giải pháp ứng viên tốt nhất trong một không gian có nhiều giải pháp tiềm năng.
  • Brute-force algorithms exist for every combinatorial problem, but they are not typically used in practice because of long run time issues. To enumerate all potential solutions, a brute-force algorithm must generate every possible combination of the input data.
  • Các thuật toán brute-force tồn tại cho mọi vấn đề tổ hợp, nhưng chúng thường không được sử dụng trong thực tế do vấn đề thời gian chạy lâu. Để liệt kê tất cả các giải pháp tiềm năng, một thuật toán brute-force phải tạo ra mọi sự kết hợp có thể của dữ liệu đầu vào.
  • Greedy algorithms solve combinatorial problems by repeatedly applying a simple rule to select the next element to include in the solution. Unlike brute-force algorithms that solve combinatorial problems by generating all potential solutions, greedy algorithms instead focus on generating just one solution.
  • Các thuật toán tham lam giải quyết các bài toán tổ hợp bằng cách lặp đi lặp lại việc áp dụng một quy tắc đơn giản để chọn phần tử tiếp theo để đưa vào giải pháp. Khác với các thuật toán brute-force giải quyết các bài toán tổ hợp bằng cách tạo ra tất cả các giải pháp tiềm năng, các thuật toán tham lam thay vào đó tập trung vào việc tạo ra chỉ một giải pháp.
  • Greedy algorithms are not always guaranteed to compute the best solution depending on the assumptions and goals of the problem. A greedy algorithm for the interval scheduling problem will not compute the correct result if we choose to complete the shortest tasks.
  • Các thuật toán tham lam không phải lúc nào cũng đảm bảo tính toán được giải pháp tốt nhất tùy thuộc vào các giả định và mục tiêu của vấn đề. Một thuật toán tham lam cho bài toán lập lịch khoảng thời gian sẽ không tính toán được kết quả chính xác nếu chúng ta chọn hoàn thành các nhiệm vụ ngắn nhất.
  • Kruskal’s algorithm and Prim’s algorithm are two examples of greedy algorithms for the minimum spanning trees problem. These algorithms are a rare example of a greedy algorithm that is guaranteed to compute the correct result.
  • Thuật toán Kruskal và thuật toán Prim là hai ví dụ về thuật toán tham lam cho bài toán cây khung tối thiểu. Những thuật toán này là một ví dụ hiếm hoi về thuật toán tham lam mà được đảm bảo sẽ tính toán đúng kết quả.
  • Reduction algorithms solve problems by transforming them into other problems. In other words, reduction algorithms delegate most of the work of solving the problem to another algorithm meant for a different problem.
  • Các thuật toán giảm thiểu giải quyết các vấn đề bằng cách chuyển đổi chúng thành các vấn đề khác. Nói cách khác, các thuật toán giảm thiểu ủy thác hầu hết công việc giải quyết vấn đề cho một thuật toán khác được thiết kế cho một vấn đề khác.
  • Reduction algorithms allow algorithm designers to rely on optimized canonical algorithms rather than designing a solution by composing algorithm design patterns, which can lead to performance or correctness bugs. Reduction algorithms also enable computer scientists to make claims about the relative difficulty of a problem.
  • Các thuật toán giảm thiểu cho phép các nhà thiết kế thuật toán dựa vào các thuật toán chuẩn hóa tối ưu thay vì thiết kế một giải pháp bằng cách kết hợp các mẫu thiết kế thuật toán, điều này có thể dẫn đến lỗi về hiệu suất hoặc độ chính xác. Các thuật toán giảm thiểu cũng cho phép các nhà khoa học máy tính đưa ra các tuyên bố về độ khó tương đối của một vấn đề.

3.5 Sample Algorithms by Problem

3.5 Các Thuật Toán Mẫu Theo Vấn Đề
  • Data structure problems focus on the storage and retrieval of elements for implementing abstract data types such as lists, sets, maps, and priority queues. Data structure problems include sorting, searching, and hashing.
  • Vấn đề cấu trúc dữ liệu tập trung vào việc lưu trữ và truy xuất các phần tử để triển khai các kiểu dữ liệu trừu tượng như danh sách, tập hợp, bản đồ và hàng đợi ưu tiên. Các vấn đề cấu trúc dữ liệu bao gồm sắp xếp, tìm kiếm và băm.
  • Searching is the problem of retrieving a target element from a collection of elements. Searching in a linear data structure such as an array list can be done using either sequential search or binary search.
  • Tìm kiếm là vấn đề lấy một phần tử mục tiêu từ một tập hợp các phần tử. Tìm kiếm trong một cấu trúc dữ liệu tuyến tính như danh sách mảng có thể được thực hiện bằng cách sử dụng tìm kiếm tuần tự hoặc tìm kiếm nhị phân.
  • Sorting is the problem of rearranging elements into a logical order, typically from least-valued (smallest) to greatest-valued (largest). Sorting is a fundamental problem not only because of the tasks that it directly solves, but also because it is a foundation for many other algorithms such as the binary search algorithm or Kruskal’s algorithm for the minimum spanning tree problem.
  • Sắp xếp là vấn đề của việc sắp xếp lại các phần tử theo một thứ tự hợp lý, thường từ giá trị thấp nhất (nhỏ nhất) đến giá trị cao nhất (lớn nhất). Sắp xếp là một vấn đề cơ bản không chỉ vì các nhiệm vụ mà nó giải quyết trực tiếp, mà còn vì nó là nền tảng cho nhiều thuật toán khác như thuật toán tìm kiếm nhị phân hoặc thuật toán Kruskal cho vấn đề cây bao trùm tối thiểu.
  • Merge sort and quicksort are two examples of divide and conquer algorithms for sorting. Heapsort is a sorting algorithm that relies on adding to a heap and then repeatedly removing each element in sorted order.
  • Sắp xếp hợp nhất và sắp xếp nhanh là hai ví dụ về thuật toán chia để trị để sắp xếp. Sắp xếp heap là một thuật toán sắp xếp dựa vào việc thêm vào một heap và sau đó liên tục loại bỏ từng phần tử theo thứ tự đã sắp xếp.
  • Hashing is the problem of assigning a meaningful integer index (hash value) for each object. Hash tables are a data structure for implementing sets and maps by applying the concept of hashing.
  • Băm là vấn đề gán một chỉ số nguyên có ý nghĩa (giá trị băm) cho mỗi đối tượng. Bảng băm là một cấu trúc dữ liệu để triển khai các tập hợp và bản đồ bằng cách áp dụng khái niệm băm.
  • Graph problems include a wide variety of problems involving the graph data type. Graph problems include traversal, minimum spanning trees, and shortest paths.
  • Vấn đề đồ thị bao gồm nhiều loại vấn đề liên quan đến kiểu dữ liệu đồ thị. Vấn đề đồ thị bao gồm duyệt, cây bao trùm nhỏ nhất và đường đi ngắn nhất.
  • Traversal is the problem of exploring all the vertices in a graph. Depth-first search and breadth-first search are both graph traversal algorithms that expand outward from a start vertex, ultimately visiting every reachable vertex.
  • Traversal là vấn đề khám phá tất cả các đỉnh trong một đồ thị. Tìm kiếm theo chiều sâu và tìm kiếm theo chiều rộng đều là các thuật toán duyệt đồ thị mở rộng ra từ một đỉnh bắt đầu, cuối cùng ghé thăm mọi đỉnh có thể tiếp cận.
  • Minimum spanning trees is the problem of finding a lowest-cost way to connect all the vertices to each other, where cost is the sum of the selected edge weights. The two canonical greedy algorithms for finding a minimum spanning tree in a graph are Kruskal’s algorithm and Prim’s algorithm.
  • Cây bao trùm tối thiểu là bài toán tìm cách kết nối tất cả các đỉnh với nhau với chi phí thấp nhất, trong đó chi phí là tổng trọng số của các cạnh được chọn. Hai thuật toán tham lam điển hình để tìm cây bao trùm tối thiểu trong một đồ thị là thuật toán Kruskal và thuật toán Prim.
  • Shortest paths is the problem of finding a lowest-cost way to get from one vertex to another. The output of a shortest paths algorithm is a shortest paths tree from the start vertex to every other vertex in the graph.
  • Đường đi ngắn nhất là bài toán tìm cách có chi phí thấp nhất để di chuyển từ một đỉnh này sang đỉnh khác. Đầu ra của một thuật toán đường đi ngắn nhất là một cây đường đi ngắn nhất từ đỉnh bắt đầu đến mọi đỉnh khác trong đồ thị.
  • Breadth-first search computes the unweighted shortest paths tree, the shortest paths in terms of the number of edges. Dijkstra’s algorithm computes the weighted shortest paths tree, the shortest paths in terms of the sum of the edge weights.
  • Tìm kiếm theo chiều rộng tính toán cây đường đi ngắn nhất không trọng số, các đường đi ngắn nhất về số lượng cạnh. Thuật toán Dijkstra tính toán cây đường đi ngắn nhất có trọng số, các đường đi ngắn nhất về tổng trọng số của các cạnh.

3.6 Computer Science Theory

3.6 Lý thuyết Khoa học Máy tính
  • Problem modeling is constrained by the model of computation, or the rules of the underlying computer that is ultimately responsible for executing the algorithm. Combinatorial explosion poses a problem for computer algorithms because our model of computation assumes computers only have a single thread of execution and only execute one basic operation on each step.
  • Mô hình hóa vấn đề bị hạn chế bởi mô hình tính toán, hoặc các quy tắc của máy tính cơ bản chịu trách nhiệm cuối cùng cho việc thực thi thuật toán. Sự bùng nổ tổ hợp đặt ra một vấn đề cho các thuật toán máy tính vì mô hình tính toán của chúng ta giả định rằng máy tính chỉ có một luồng thực thi duy nhất và chỉ thực hiện một phép toán cơ bản trong mỗi bước.
  • A Turing machine is an abstract model of computation for executing any computer algorithm. A Turing machine describes computers in terms of three key ideas: a memory bank, an instruction table, and a program counter.
  • Một máy Turing là một mô hình trừu tượng của tính toán để thực hiện bất kỳ thuật toán máy tính nào. Một máy Turing mô tả máy tính dựa trên ba ý tưởng chính: một ngân hàng bộ nhớ, một bảng hướng dẫn và một bộ đếm chương trình.
  • Although today’s computers are much more efficient than the first computers that realized the Turing machine, most computers still rely on the same fundamental assumptions about how to execute algorithms. Even as computers become faster over time inefficient algorithms still cannot be used to solve any problems larger than a few thousand elements.
  • Mặc dù ngày nay các máy tính hiệu quả hơn nhiều so với những máy tính đầu tiên đã hiện thực hóa máy Turing, hầu hết các máy tính vẫn dựa vào những giả định cơ bản giống nhau về cách thực thi các thuật toán. Ngay cả khi các máy tính trở nên nhanh hơn theo thời gian, các thuật toán không hiệu quả vẫn không thể được sử dụng để giải quyết bất kỳ vấn đề nào lớn hơn vài nghìn phần tử.
  • The complexity of a problem is the complexity (i.e., the time or memory resources required) of the most efficient algorithms for solving the problem. In this chapter, we have focused on solving problems known to have polynomial time algorithms that can be described with a polynomial expression such as O(1), O(log N), O(N), O(N log N), O(N2), O(N3).
  • Độ phức tạp của một bài toán là độ phức tạp (tức là, thời gian hoặc tài nguyên bộ nhớ cần thiết) của các thuật toán hiệu quả nhất để giải quyết bài toán đó. Trong chương này, chúng ta đã tập trung vào việc giải quyết các bài toán được biết là có các thuật toán thời gian đa thức có thể được mô tả bằng một biểu thức đa thức như O(1), O(log N), O(N), O(N log N), O(N2), O(N3).
  • Nondeterministic polynomial (NP) time complexity class refers to all problems that can be solved in polynomial time by a nondeterministic algorithm. A nondeterministic algorithm is a kind of algorithm that can rely on the special power of exploring infinitely many possible “alternate universes” in order to complete a computation.
  • Lớp độ phức tạp thời gian đa thức không xác định (NP) đề cập đến tất cả các vấn đề có thể được giải quyết trong thời gian đa thức bởi một thuật toán không xác định. Một thuật toán không xác định là một loại thuật toán có thể dựa vào sức mạnh đặc biệt của việc khám phá vô số "vũ trụ thay thế" có thể có để hoàn thành một phép tính.
  • Technically, all P problems are also NP problems because we already have deterministic algorithms for solving them and therefore do not need to rely on the special power of nondeterminism. NP-complete refers to all the hardest NP problems—the combinatorial problems for which we do not have deterministic polynomial-time algorithms.
  • Về mặt kỹ thuật, tất cả các vấn đề P cũng là các vấn đề NP vì chúng ta đã có các thuật toán xác định để giải quyết chúng và do đó không cần phải dựa vào sức mạnh đặc biệt của tính không xác định. NP-complete đề cập đến tất cả các vấn đề NP khó nhất—các vấn đề tổ hợp mà chúng ta không có các thuật toán đa thức xác định.
  • Longest paths and the traveling salesperson problem (TSP) are two well-known examples of NP-complete problems. What makes both these problems difficult is that we do not have a simple rule for selecting the next element to include in the solution.
  • Các đường đi dài nhất và bài toán người bán hàng du lịch (TSP) là hai ví dụ nổi tiếng về các bài toán NP-đầy đủ. Điều làm cho cả hai bài toán này trở nên khó khăn là chúng ta không có một quy tắc đơn giản nào để chọn phần tử tiếp theo để đưa vào giải pháp.
  • All NP-complete problems can be reduced to all the others, so an algorithm for solving any NP-complete problem solves every NP-complete problem. The question of P versus NP asks whether it is possible to design a deterministic polynomial-time algorithm for solving any—and therefore all—of these NP-complete problems.
  • Tất cả các bài toán NP-đầy đủ có thể được giảm xuống tất cả các bài toán khác, vì vậy một thuật toán để giải quyết bất kỳ bài toán NP-đầy đủ nào sẽ giải quyết mọi bài toán NP-đầy đủ. Câu hỏi về P so với NP đặt ra liệu có thể thiết kế một thuật toán xác định thời gian đa thức để giải quyết bất kỳ bài toán NP-đầy đủ nào - và do đó là tất cả - những bài toán NP-đầy đủ này hay không.
  • Most theoretical computer scientists believe that it is impossible to design an efficient algorithm for longest paths, TSP, or any other NP-complete problems. An efficient algorithm for any one NP-complete problems would not only directly solve routing and logistics problems but would also enable massive advancements in drug discovery through scientific simulation, for instance. It would also break essentially all modern Internet security and password systems—among thousands of other problems.
  • Hầu hết các nhà khoa học máy tính lý thuyết tin rằng không thể thiết kế một thuật toán hiệu quả cho các đường đi dài nhất, TSP, hoặc bất kỳ vấn đề NP-đầy đủ nào khác. Một thuật toán hiệu quả cho bất kỳ vấn đề NP-đầy đủ nào sẽ không chỉ giải quyết trực tiếp các vấn đề về định tuyến và logistics mà còn cho phép những tiến bộ lớn trong việc phát hiện thuốc thông qua mô phỏng khoa học, chẳng hạn. Nó cũng sẽ phá vỡ hầu như tất cả các hệ thống bảo mật Internet hiện đại và hệ thống mật khẩu—trong số hàng ngàn vấn đề khác.
