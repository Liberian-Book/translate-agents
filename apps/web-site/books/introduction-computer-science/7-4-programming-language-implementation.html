Preprocessing

Tiền xử lý

The single process that takes the source code the programmer creates and transforms it into another language is called compilation. In short, it is the rendering from one language into another and includes a deconstruction of the input, and its product may be machine language. Modern compilation usually starts with preprocessing, a step in which the source code is manipulated to ready it for the compilation stage. Some of the actions the preprocessor can take are as follows:

Quá trình duy nhất chuyển đổi mã nguồn mà lập trình viên tạo ra thành một ngôn ngữ khác được gọi là biên dịch. Nói ngắn gọn, đó là việc chuyển đổi từ một ngôn ngữ sang ngôn ngữ khác và bao gồm việc phân tích cấu trúc của đầu vào, và sản phẩm của nó có thể là ngôn ngữ máy. Biên dịch hiện đại thường bắt đầu với tiền xử lý, một bước trong đó mã nguồn được thao tác để chuẩn bị cho giai đoạn biên dịch. Một số hành động mà trình tiền xử lý có thể thực hiện như sau:

  • Removing any comments and white space
  • Loại bỏ bất kỳ comment nào và khoảng trắng
  • Executing a preprocessor directive, which describes resources the program needs to compile, usually files to insert into the source code. The C/C++ preprocessor provides a fine example.
    1. The #include directive of C/C++ deals with a variety of files such as header or standard files containing the definitions of objects and functions from the API that are going to be used in the program. It can also take care of user-defined files or modules.
    2. Chỉ thị #include của C/C++ xử lý nhiều loại tệp khác nhau như tệp tiêu đề hoặc tệp chuẩn chứa các định nghĩa của đối tượng và hàm từ API sẽ được sử dụng trong chương trình. Nó cũng có thể xử lý các tệp do người dùng định nghĩa hoặc modules.
    3. The #define directive of C/C++ names a piece of code for the preprocessor to replace every time it sees the name.
    4. Chỉ thị #define trong C/C++ đặt tên cho một đoạn mã để trình tiền xử lý thay thế mỗi khi nó thấy tên đó.
    5. The #ifdef directive of C/C++ tells the compiler to include a specified piece of code in compilation depending upon some condition.
    6. Chỉ thị #ifdef của C/C++ cho trình biên dịch biết để bao gồm một đoạn mã được chỉ định trong quá trình biên dịch tùy thuộc vào một số điều kiện.
  • Other tasks include pre-identifying high-level constructs such as loops and functions.
  • Các nhiệm vụ khác bao gồm việc xác định trước các cấu trúc cấp cao như vòng lặp và functions.

Compilation

Biên dịch

The phases of compilation are grouped into three stages that are usually executed in three passes through the preprocessed source code:

Các giai đoạn biên dịch được nhóm thành ba giai đoạn thường được thực hiện qua ba lần xử lý mã nguồn đã được tiền xử lý:

  • front end that is responsible for the analysis of source code
  • front end chịu trách nhiệm cho việc phân tích mã nguồn
  • middle end that is responsible for performing optimizations of the code
  • phần giữa cuối chịu trách nhiệm thực hiện tối ưu hóa mã code
  • back end (or code generator) that is responsible for the production of the target code
  • back end (hoặc trình tạo mã) chịu trách nhiệm sản xuất mã mục tiêu

Front-End Compiler Structure

Cấu trúc Biên dịch viên Giao diện Người dùng

The front end is responsible for analyzing the source code for syntax, semantics, and other tasks. The first part of this process is lexical analysis, which converts the source code strings of characters into tokens. These are sequences of compiler recognizable atomic symbols which make it much easier for the next steps to recognize them.

Phần giao diện người dùng chịu trách nhiệm phân tích mã nguồn về cú pháp, ngữ nghĩa và các nhiệm vụ khác. Phần đầu tiên của quá trình này là phân tích từ vựng, chuyển đổi mã nguồn string các ký tự thành token. Đây là các chuỗi ký hiệu nguyên tử mà trình biên dịch có thể nhận diện, giúp cho các bước tiếp theo dễ dàng nhận ra chúng hơn.

The process proceeds to syntax analysis, usually referred to as parsing or reading the code to make sure it conforms with the syntax rules of the language. This is done to test conformability logically by breaking code into separate parts.

Quá trình tiếp tục đến phân tích cú pháp, thường được gọi là parsing hoặc đọc mã để đảm bảo nó tuân thủ các quy tắc cú pháp của ngôn ngữ. Điều này được thực hiện để kiểm tra tính tuân thủ một cách logic bằng cách chia mã thành các phần riêng biệt.

The next step is semantic analysis, which is the discovery of meaning in the code. It takes care of type checking in strongly typed languages. It also performs binding, which associates variable and function references with their declarations and definitions. The compiler runs a static semantic analysis which concerns itself only with the source code without testing inputs.

Bước tiếp theo là phân tích ngữ nghĩa, đây là quá trình khám phá ý nghĩa trong mã. Nó đảm bảo kiểm tra kiểu trong các ngôn ngữ strongly typed. Nó cũng thực hiện việc liên kết, liên kết các variable và tham chiếu hàm với các khai báo và định nghĩa của chúng. Trình biên dịch thực hiện một phân tích ngữ nghĩa tĩnh, chỉ quan tâm đến mã nguồn mà không kiểm tra các đầu vào.

Semantic analysis cannot figure out all meaning in the code. Many languages also use dynamic binding (late binding) that defers the binding of certain elements such as objects and methods until runtime. This is particularly true of OOP languages which support inheritance and polymorphism. Some processes, such as when an array goes out of bounds, will not be known until run time, and are part of the program’s dynamic semantics.

Phân tích ngữ nghĩa không thể xác định tất cả ý nghĩa trong mã. Nhiều ngôn ngữ cũng sử dụng liên kết động (late binding) mà hoãn việc liên kết của một số element như đối tượng và phương thức cho đến thời gian chạy. Điều này đặc biệt đúng với các ngôn ngữ OOP hỗ trợ inheritance và polymorphism. Một số quy trình, chẳng hạn như khi một array vượt quá giới hạn, sẽ không được biết cho đến thời gian chạy, và là một phần của ngữ nghĩa động của chương trình.

Semantic analysis concludes with the creation and management of the symbol table, a data structure that is used to connect every symbol with necessary information such as data type, scope, and memory location.

Phân tích ngữ nghĩa kết thúc với việc tạo ra và quản lý bảng ký hiệu, một cấu trúc dữ liệu được sử dụng để kết nối mỗi ký hiệu với thông tin cần thiết như kiểu dữ liệu, scope, và vị trí bộ nhớ.

Intermediate Form

Hình thức trung gian

The result created after semantic analysis when the program passes all checks is called intermediate form (IF). The nature of the IF is often chosen for machine independence and ease of optimization. IFs usually resemble the machine code for some imaginary idealized machine. An example is managed code which is targeted to run under a particular runtime environment. This is true of C# and other Microsoft.net languages. They are designed to run under its CLR, which manages the execution of Microsoft’s .NET languages. In this case, the purpose is to allow code from the different languages to work well together at execution time.

Kết quả được tạo ra sau phân tích ngữ nghĩa khi chương trình vượt qua tất cả các kiểm tra được gọi là hình thức trung gian (IF). Bản chất của IF thường được chọn để đảm bảo tính độc lập với máy và dễ dàng tối ưu hóa. IF thường giống như mã máy cho một máy tưởng tượng lý tưởng nào đó. Một ví dụ là mã được quản lý mà được nhắm đến để chạy dưới một môi trường thời gian chạy cụ thể. Điều này đúng với C# và các ngôn ngữ Microsoft.net khác. Chúng được thiết kế để chạy dưới CLR, cái quản lý việc thực thi các ngôn ngữ .NET của Microsoft. Trong trường hợp này, mục đích là cho phép mã từ các ngôn ngữ khác nhau hoạt động tốt cùng nhau trong thời gian thực thi.

Back-End Compiler Structure

Cấu trúc Biên dịch viên Phía Sau

The back-end process is known as code generation, the transformation of the code to the target or object language. It uses the intermediate form of the code in combination with the symbol table to carry this out. As previously stated, the final produced code is not necessarily machine language. In hybrid implementations, such as in Java and others, the code will still be a type of intermediate form and it is left for another process to turn it into machine code, usually at runtime.

Quá trình phía sau được gọi là tạo mã, là sự chuyển đổi mã sang ngôn ngữ mục tiêu hoặc ngôn ngữ đối tượng. Nó sử dụng dạng trung gian của mã kết hợp với bảng ký hiệu để thực hiện điều này. Như đã đề cập trước đó, mã cuối cùng được sản xuất không nhất thiết phải là ngôn ngữ máy. Trong hybrid implementation, chẳng hạn như trong Java và các ngôn ngữ khác, mã vẫn sẽ là một loại dạng trung gian và nó được để cho một quá trình khác chuyển đổi thành mã máy, thường là trong thời gian chạy.

Pure compilation code generation generally produces this phase (and all compile phases) while also relying on the symbol table, which is the structure responsible for following identifiers within a program and tracking the work of the compiler. Once compilation is complete, the debugger may retain the symbol table.

Mã nguồn biên dịch thuần túy thường tạo ra giai đoạn này (và tất cả các giai đoạn biên dịch) trong khi cũng dựa vào bảng ký hiệu, là cấu trúc chịu trách nhiệm theo dõi identifier trong một chương trình và theo dõi công việc của trình biên dịch. Khi quá trình biên dịch hoàn tất, trình gỡ lỗi có thể giữ lại bảng ký hiệu.

The back-end phase of the compiler may also perform machine-independent code generation. The purpose of this is to allow a piece of source code to generate instructions that will run on different platforms without change such as Windows and Android. Java is a great example of this, as referenced in Figure 7.25.

Giai đoạn back-end của trình biên dịch cũng có thể thực hiện việc tạo mã độc lập với máy. Mục đích của điều này là cho phép một đoạn mã nguồn tạo ra các lệnh sẽ chạy trên các nền tảng khác nhau mà không cần thay đổi, chẳng hạn như Windows và Android. Java là một ví dụ tuyệt vời cho điều này, như đã được đề cập trong Hình 7.25.

This can then be run in any environment for which a JVM has been built.

Compilation of Interpreted Languages

Biên dịch các ngôn ngữ thông dịch

In some languages, compilers are present, but they aren’t pure and only perform a selective compilation of pieces, or pre-processing, of the remaining source. Occasionally the compiler generates code that builds expectations around decisions that won’t be completed until runtime. If these assumptions are sound, the code runs very fast. If not, a dynamic check reverts to the interpreter.

Trong một số ngôn ngữ, các trình biên dịch có mặt, nhưng chúng không hoàn toàn thuần khiết và chỉ thực hiện việc biên dịch chọn lọc các phần, hoặc tiền xử lý, của mã nguồn còn lại. Đôi khi, trình biên dịch tạo ra mã mà xây dựng các kỳ vọng xung quanh các quyết định sẽ không được hoàn thành cho đến khi chạy thời gian. Nếu những giả định này là hợp lý, mã sẽ chạy rất nhanh. Nếu không, một kiểm tra động sẽ quay trở lại trình thông dịch.

Dynamic and Just-in-Time Compilation

Biên dịch Động và Biên dịch Ngay Lập Tức

Sometimes a program delays compilation until the last minute. In Java, a bytecode is a set of instructions for a virtual machine. The process of just-in-time (JIT) compilation is when intermediate code, which is the language translation phase that produces a code level between the source code and the object code, gets its final compilation (or usually interpretation) phase right at the start of runtime. Bytecode is the standard format for distribution of Java programs to any runtime platform such as Windows, macOS, and Linux. The bytecode is interpreted by a Java virtual machine (JVM) that has been implemented by the producer specifically for their platform. Since there is a JVM for macOS but not for Mac IOS, Java is incompatible with iPhones.

Đôi khi một chương trình trì hoãn biên dịch cho đến phút cuối. Trong Java, một bytecode là một tập hợp các hướng dẫn cho một máy ảo. Quá trình của biên dịch ngay lập tức (JIT) là khi mã trung gian, đây là giai đoạn dịch ngôn ngữ tạo ra một cấp độ mã giữa mã nguồn và mã đối tượng, nhận được giai đoạn biên dịch cuối cùng (hoặc thường là diễn giải) ngay tại thời điểm bắt đầu thực thi. Bytecode là định dạng tiêu chuẩn để phân phối các chương trình Java đến bất kỳ nền tảng thực thi nào như Windows, macOS và Linux. Bytecode được diễn giải bởi một Java virtual machine (JVM) đã được nhà sản xuất triển khai đặc biệt cho nền tảng của họ. Vì có một JVM cho macOS nhưng không có cho Mac IOS, Java không tương thích với iPhone.

Assembly

Lắp ráp

Most compilers generate assembly language that must subsequently be processed by an assembler to create an object file. The process of converting a low-level assembly language of the compiler into machine language that the computer can execute in binary form is called assembly. Assembly language is a very low-level language that has a strong correspondence with the machine language but is still humanly readable, as visible in Figure 4.7. Post-compilation assembly has some distinct advantages, such as expediting debugging so that the language is easier to read while making sharing possible among compilers. It also isolates the compiler from changes needed in the format of machine language files; for example, when computer chips change, only the assembler must be changed.

Hầu hết các compiler tạo ra ngôn ngữ assembly cần phải được xử lý bởi một assembler để tạo ra một tệp đối tượng. Quá trình chuyển đổi ngôn ngữ assembly cấp thấp của compiler ngôn ngữ máy mà máy tính có thể thực thi dưới dạng nhị phân được gọi là lắp rápNgôn ngữ hợp ngữ là một ngôn ngữ rất cấp thấp có sự tương ứng mạnh mẽ với ngôn ngữ máy nhưng vẫn có thể đọc được bởi con người, như thấy trong Hình 4.7. Việc biên dịch sau khi biên dịch có một số lợi thế rõ ràng, chẳng hạn như tăng tốc độ gỡ lỗi để ngôn ngữ dễ đọc hơn trong khi cho phép chia sẻ giữa các compiler. Nó cũng tách biệt compiler khỏi những thay đổi cần thiết trong định dạng của các tệp ngôn ngữ máy; ví dụ, khi các chip máy tính thay đổi, chỉ cần thay đổi bộ lắp ráp.

A computer’s hardware does not implement the assembly-level instruction set; it is run by the interpreter. The interpreter is written in low-level instructions (microcode or firmware). These items are housed in read-only memory and executed by the hardware.

Phần cứng của một máy tính không thực hiện tập hợp lệnh ở cấp độ lắp ráp; nó được chạy bởi trình thông dịch. Trình thông dịch được viết bằng các lệnh cấp thấp (mã vi xử lý hoặc phần mềm nhúng). Những mục này được lưu trữ trong bộ nhớ chỉ đọc và được thực thi bởi phần cứng.

Linking

Liên kết

Language implementations that are intended for the construction of large programs support separate compilation where pieces of the program can be compiled and built independently. Once compilation is complete, these pieces called compilation units are rejoined by a linker.

Các triển khai ngôn ngữ được thiết kế cho việc xây dựng các chương trình lớn hỗ trợ biên dịch tách biệt nơi các phần của chương trình có thể được biên dịch và xây dựng độc lập. Khi quá trình biên dịch hoàn tất, các phần này được gọi là đơn vị biên dịch sẽ được kết hợp lại bởi một trình liên kết.

An important function of the linker is to join modules of precompiled libraries of subroutines, such as those in the language API or precompiled user defined functions, into the final program so that they can be separately compiled. If the program draws from a library, it will still need to be linked. Additionally, a static linker produces an executable object file by completing its tasks prior to the program running, while a dynamic linker allows the program to be carried over to memory for execution after it runs.

Một function quan trọng của trình liên kết là kết hợp các mô-đun của thư viện đã biên dịch sẵn các thủ tục, chẳng hạn như những cái trong API ngôn ngữ hoặc các function do người dùng định nghĩa đã biên dịch sẵn, vào chương trình cuối cùng để chúng có thể được biên dịch riêng biệt. Nếu chương trình sử dụng một thư viện, nó vẫn cần được liên kết. Thêm vào đó, một static linker tạo ra một tệp đối tượng thực thi bằng cách hoàn thành các nhiệm vụ của nó trước khi chương trình chạy, trong khi một dynamic linker cho phép chương trình được chuyển vào bộ nhớ để thực thi sau khi nó chạy.

Runtime Program Management

Quản lý Chương trình Thời gian chạy

The runtime system refers to the set of libraries that the language implementation depends upon for correct operation. The compiler generates program-speciﬁc metadata, data about data, that the runtime must inspect to do its job. It is recommended that the compiler and runtime system be developed together to avoid some of the following issues:

Hệ thống thời gian chạy đề cập đến tập hợp các thư viện mà việc triển khai ngôn ngữ phụ thuộc vào để hoạt động chính xác. Trình biên dịch tạo ra metadata cụ thể cho chương trình, dữ liệu về dữ liệu, mà hệ thống thời gian chạy phải kiểm tra để thực hiện công việc của nó. Chúng ta nên phát triển trình biên dịch và hệ thống thời gian chạy cùng nhau để tránh một số vấn đề sau đây:

  • Garbage collection: the ability to dynamically destroy program objects when no longer needed and recover their memory
  • Thu gom rác: khả năng hủy động các đối tượng chương trình khi không còn cần thiết và khôi phục bộ nhớ của chúng.
  • Variable numbers of arguments: for languages that allow differing numbers and types for function arguments only encountered at runtime; languages support function overriding, such as Java, C++, and C#
  • Số lượng argument khác nhau: cho các ngôn ngữ cho phép số lượng và loại khác nhau cho các đối số hàm chỉ được gặp tại thời điểm chạy; các ngôn ngữ hỗ trợ ghi đè hàm, chẳng hạn như Java, C++ và C#
  • Exception handling: recovery implemented when a program encounters a runtime error or exception
  • Xử lý exception: phục hồi được thực hiện khi một chương trình gặp phải lỗi thời gian chạy hoặc exception
  • Event handling: the ability to respond to runtime occurrences such as a button click or other unpredictable event
  • Xử lý sự kiện: khả năng phản hồi các sự kiện xảy ra trong thời gian chạy như nhấp chuột vào nút hoặc các sự kiện không thể đoán trước khác.
  • Coroutine and thread implementation: languages where implement can handle concurrency and parallelism
  • Triển khai Coroutine và luồng: các ngôn ngữ nơi triển khai có thể xử lý concurrency và parallelism

Virtual Machines

Máy ảo

A virtual machine (VM) provides a complete program execution environment that is the reproduction of a computer architecture. Many modern languages employ virtual machines as their runtime environment. In general computer science, VMs can refer to a system VM as supplied by such vendors as VMware, which provide all the hardware facilities needed to run a standard OS so that programs built for one OS can run on another.

Một máy ảo (VM) cung cấp một môi trường thực thi chương trình hoàn chỉnh, tái tạo kiến trúc máy tính. Nhiều ngôn ngữ hiện đại sử dụng máy ảo như môi trường thực thi của chúng. Trong khoa học máy tính nói chung, VM có thể đề cập đến một máy ảo hệ thống do các nhà cung cấp như VMware cung cấp, cung cấp tất cả các tiện ích phần cứng cần thiết để chạy một hệ điều hành tiêu chuẩn, để các chương trình được xây dựng cho một hệ điều hành có thể chạy trên một hệ điều hành khác.

However, with HLLs we make another distinct type of VM called a process VM which provides the environment needed by a single user-level process. Perhaps the first and best example is the Java virtual machine (JVM) because its purpose was to elegantly and efficiently meet a main design goal of the language, which was hardware and OS independence.

Tuy nhiên, với HLLs, chúng ta tạo ra một loại VM khác biệt gọi là VM quy trình, cung cấp môi trường cần thiết cho một quy trình cấp người dùng duy nhất. Có lẽ ví dụ đầu tiên và tốt nhất là máy ảo Java (JVM) vì mục đích của nó là đáp ứng một cách thanh lịch và hiệu quả một mục tiêu thiết kế chính của ngôn ngữ, đó là độc lập với phần cứng và hệ điều hành.

The JVM is a complete runtime manager and interpreter. As we have learned, the Java compiler generates as output an intermediate form of code known as bytecode which is placed in object files with a .class extension. This bytecode is identical for every platform and OS on which Java may be run. The JVM is designed to take the last step of interpreting the bytecode into the machine language and the OS instruction set of the target architecture. It is also the runtime manager for the process. A more recent invention is the Java JIT compiler, which may call for more speed than a JVM interpreter can produce. Figure 7.26 illustrates these principles.

JVM là một trình quản lý và thông dịch hoàn chỉnh. Như chúng ta đã học, trình biên dịch Java tạo ra đầu ra là một dạng mã trung gian được gọi là bytecode, được đặt trong các tệp đối tượng với phần mở rộng .class. Bytecode này là giống hệt nhau cho mọi nền tảng và hệ điều hành mà Java có thể chạy. JVM được thiết kế để thực hiện bước cuối cùng là thông dịch bytecode thành ngôn ngữ máy và tập lệnh hệ điều hành của kiến trúc mục tiêu. Nó cũng là trình quản lý thời gian chạy cho quá trình này. Một phát minh gần đây hơn là trình biên dịch Java JIT, có thể yêu cầu tốc độ nhanh hơn so với những gì một trình thông dịch JVM có thể tạo ra. Hình 7.26 minh họa những nguyên tắc này.

A JVM manages the runtime as well as provides storage management functionality that embraces features, including class structures (metadata), heaps, register sets, thread stacks, and code storage.

Một JVM quản lý thời gian chạy cũng như cung cấp chức năng quản lý bộ nhớ bao gồm các tính năng, bao gồm cấu trúc lớp (siêu dữ liệu), vùng nhớ heap, tập hợp thanh ghi, ngăn xếp luồng và lưu trữ mã.

The Microsoft CLR is a similar animal but directed for the Microsoft .NET platform and all its component languages. CLR and JVM share features including multithreading and stack-based VMs, and both have garbage collection. Additionally, both use platform-independence, are self-descriptive, and contain bytecode notation.

Microsoft CLR là một khái niệm tương tự nhưng được hướng đến nền tảng Microsoft .NET và tất cả các ngôn ngữ thành phần của nó. CLR và JVM chia sẻ các tính năng bao gồm đa luồng và máy ảo dựa trên ngăn xếp, và cả hai đều có thu gom rác. Ngoài ra, cả hai đều sử dụng tính độc lập với nền tảng, có khả năng tự mô tả và chứa ký hiệu bytecode.

Symbolic Debugging

Gỡ lỗi Biểu tượng

While debuggers are present in most virtual machines and integrated program development environments (IDEs) and provided by programming language interpreters, they also come as standalone tools. Symbolic debuggers understand high-level syntax. In short, a debugger finds errors in programs. It can also set parameters for stopping an execution should it reach a certain point in the source code or if a constant is read.

Trong khi các trình gỡ lỗi có mặt trong hầu hết các máy ảo và môi trường phát triển chương trình tích hợp (IDEs) và được cung cấp bởi các trình thông dịch ngôn ngữ lập trình, chúng cũng xuất hiện dưới dạng các công cụ độc lập. Các trình gỡ lỗi ký hiệu hiểu cú pháp cấp cao. Nói ngắn gọn, một trình gỡ lỗi tìm các lỗi trong chương trình. Nó cũng có thể thiết lập các tham số để dừng một quá trình thực thi nếu nó đạt đến một điểm nhất định trong mã nguồn hoặc nếu một hằng số được đọc.

Code Optimization and Improvement

Tối ưu hóa và Cải tiến Mã

The goal of code optimization is to rework parts of your code for efficiency. Some of the problem areas of optimization are redundant computations, as well as inefficient use of the hardware registers, multiple functional units (input, output), memory, and cache.

Mục tiêu của tối ưu hóa mã là cải tiến các phần của mã của bạn để đạt hiệu quả. Một số vấn đề trong tối ưu hóa bao gồm các phép toán dư thừa, cũng như việc sử dụng không hiệu quả các thanh ghi phần cứng, nhiều đơn vị chức năng (đầu vào, đầu ra), bộ nhớ và bộ nhớ đệm.

We can interpret the results of optimization to mean fast and/or decreasing memory requirements. Optimization is best carried out at multiple levels, one of which is at the basic block level. A basic block is a minimal length sequence of instructions that will always execute in its entirety if it executes at all, equivalent to a code block. Code improvement at the level of basic blocks is known as local optimization, consisting of eliminating redundant operations (unnecessary loads, common subexpression calculations), providing effective instruction scheduling, and providing register allocation.

Chúng ta có thể diễn giải kết quả của việc tối ưu hóa để hiểu là yêu cầu bộ nhớ nhanh và/hoặc giảm. Việc tối ưu hóa tốt nhất được thực hiện ở nhiều cấp độ, một trong số đó là ở cấp độ basic block. Một basic block là một chuỗi lệnh có độ dài tối thiểu mà sẽ luôn được thực thi hoàn toàn nếu nó được thực thi, tương đương với một code block. Cải thiện mã ở cấp độ basic blocks được gọi là local optimization, bao gồm việc loại bỏ các thao tác thừa (các tải không cần thiết, các phép toán con expression phổ biến), cung cấp lịch trình lệnh hiệu quả và cung cấp phân bổ thanh ghi.

At higher levels, compilers review and analyze all subroutines for further improvements. The code improvements at multiple layers that include loop performance improvement, register allocation, and instruction scheduling is called global optimization.

Ở các cấp độ cao hơn, các trình biên dịch xem xét và phân tích tất cả các thủ tục con để cải thiện thêm. Các cải tiến mã ở nhiều lớp bao gồm cải thiện hiệu suất vòng lặp, phân bổ thanh ghi và lập lịch lệnh được gọi là tối ưu hóa toàn cục.

Understanding Optimization

Hiểu về Tối ưu hóa

The medical industry views code optimization as a must-have. Most medical operations make use of patient portals for communication between patients and the medical practice. This requires both speed and platform portability such as Windows and Android. Because of this, Java is the language of choice for these applications. Why is it important for programmers to understand code optimization techniques? Should they only rely on the optimizing compiler provided for the HLL they use? Why or why not? Will you become a better programmer by understanding the way that lower-level code works in order to have a high-level view of optimization?

Ngành y tế coi tối ưu hóa mã là điều cần thiết. Hầu hết các hoạt động y tế sử dụng cổng thông tin bệnh nhân để giao tiếp giữa bệnh nhân và cơ sở y tế. Điều này yêu cầu cả tốc độ và tính portability của nền tảng như Windows và Android. Chính vì vậy, Java là ngôn ngữ được ưa chuộng cho những ứng dụng này. Tại sao điều quan trọng là lập trình viên phải hiểu các kỹ thuật tối ưu hóa mã? Họ có nên chỉ dựa vào trình biên dịch tối ưu hóa được cung cấp cho HLL mà họ sử dụng không? Tại sao hoặc tại sao không? Bạn có trở thành một lập trình viên giỏi hơn bằng cách hiểu cách mà mã cấp thấp hoạt động để có cái nhìn tổng quát về tối ưu hóa không?

As with code optimization, code improvement also aims to increase execution speed. Code improvement focuses on eliminating basic blocks redundancy, loop improvements, and instruction scheduling. The biggest area of improvement focuses on the review and enhancement of the behavior of loops. Reordering loops can be difficult but rewarding as all data dependencies must be respected (loop-carried dependencies).

Cũng giống như tối ưu hóa mã, cải tiến mã cũng nhằm tăng tốc độ thực thi. Cải tiến mã tập trung vào việc loại bỏ sự dư thừa của các khối cơ bản, cải tiến vòng lặp và lập lịch hướng dẫn. Khu vực cải tiến lớn nhất tập trung vào việc xem xét và nâng cao hành vi của các vòng lặp. Sắp xếp lại các vòng lặp có thể khó khăn nhưng mang lại phần thưởng vì tất cả các phụ thuộc dữ liệu phải được tôn trọng (các phụ thuộc do vòng lặp mang lại).

The conclusion that one can form based on code optimization and code improvement is that the “need for speed” is paramount in today’s global software and internet environments.

Kết luận mà chúng ta có thể rút ra dựa trên tối ưu hóa mã và cải thiện mã là “nhu cầu về tốc độ” là điều quan trọng hàng đầu trong môi trường phần mềm và internet toàn cầu ngày nay.

Concepts In Practice

Các Khái Niệm Trong Thực Hành

Optimizing Your Code

Tối ưu hóa mã của bạn

Did you know that compilers can often improve the performance of your code? This process is called optimization. Optimizers can make your code run faster by using techniques such as removing unnecessary calculations, improving memory usage, and reorganizing code for better efficiency.

Bạn có biết rằng các trình biên dịch thường có thể cải thiện hiệu suất của mã của bạn không? Quá trình này được gọi là tối ưu hóa. Các trình tối ưu hóa có thể làm cho mã của bạn chạy nhanh hơn bằng cách sử dụng các kỹ thuật như loại bỏ các phép tính không cần thiết, cải thiện việc sử dụng bộ nhớ và tổ chức lại mã để đạt được hiệu quả tốt hơn.

By understanding optimization techniques, you can write smoother code and use fewer resources. As a side note, mainstream programming language compilers provided by Microsoft and Oracle are designed to optimize the execution of programs. Microsoft’s .Net framework uses virtual machines that manage the CLR of various programming languages. The intermediate byte code generated by compilers that target these virtual machines is optimized using some of the techniques described in this chapter.

Bằng cách hiểu các kỹ thuật tối ưu hóa, bạn có thể viết mã mượt mà hơn và sử dụng ít tài nguyên hơn. Như một lưu ý bên lề, các trình biên dịch ngôn ngữ lập trình chính thống do Microsoft và Oracle cung cấp được thiết kế để tối ưu hóa việc thực thi các chương trình. Khung .Net của Microsoft sử dụng các máy ảo quản lý CLR của các ngôn ngữ lập trình khác nhau. Mã byte trung gian được tạo ra bởi các trình biên dịch nhắm đến các máy ảo này được tối ưu hóa bằng một số kỹ thuật được mô tả trong chương này.
